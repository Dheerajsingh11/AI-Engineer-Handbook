Section 01 BeginnerStart from zero

Assumed knowledge

The RAG skeleton from Topic 4.1 and embedding input limits from Topic 4.2.

Ingestion turns documents into searchable chunks. Load, parse, clean, split, embed, store. Six steps, and it is where most of the real engineering time in a RAG project goes.

Why documents are split at all

Three independent reasons, and they push in different directions — which is why chunking is a trade-off rather than a setting.

  1. Embedding models have input limits. Most cap at 512 tokens. Text beyond the limit is silently truncated, so a 40-page document becomes an embedding of its first page.
  2. One vector cannot represent many topics. Embed a whole document covering pricing, shipping and returns and you get the average of three meanings — a vector that sits near nothing in particular and matches no specific query well.
  3. Context is a budget. Retrieving whole documents fills the window with mostly irrelevant text, which costs money and, per the "lost in the middle" effect, actively degrades the answer.
The trade-off in one sentence

Small chunks match precisely but lose context; large chunks preserve context but match vaguely. Everything in Section 03 is an attempt to get both, and the best techniques do so by decoupling what you index from what you return.

The words, in plain English

Repeating the tail of one chunk at the start of the next, so facts spanning a boundary survive.

OCR

Section 02 IntermediateParsing, and why PDFs are hostile

PDF is a page description format. It stores instructions like "draw this glyph at these coordinates". It does not store paragraphs, reading order, table structure, or which text is a heading. All of that must be inferred from geometry.

Validate your parse before you trust your pipeline

A silently bad parse produces a RAG system that confidently retrieves garbage, and it is nearly invisible downstream. Add automatic checks at ingest: assert extracted text length is plausible relative to page count; flag documents where extraction yields under ~100 characters per page as probable scans needing OCR; detect and strip lines repeating on more than half the pages; and manually read the extracted text of five documents before building anything on top of it. That last step costs twenty minutes and routinely saves weeks.

PythonRecursive, structure-aware and semantic chunking
import re, numpy as np

# ---------- 1. Recursive character: the default ------------------
def recursive_chunk(text, size=800, overlap=100,
                    separators=("\n\n", "\n", ". ", " ", "")):
    """Try to split on the most meaningful separator that yields
    pieces under `size`. Fall back to finer separators only where
    a piece is still too large."""
    if len(text) <= size:
        return [text] if text.strip() else []

    sep = next((s for s in separators
                if s and any(len(p) <= size for p in text.split(s))), "")

    if not sep:                                # hard cut, last resort
        return [text[i:i + size] for i in range(0, len(text), size - overlap)]

    chunks, current = [], ""
    for piece in text.split(sep):
        candidate = current + sep + piece if current else piece
        if len(candidate) <= size:
            current = candidate
        else:
            if current:
                chunks.append(current)
            # A piece bigger than `size` recurses with a finer separator
            if len(piece) > size:
                chunks.extend(recursive_chunk(piece, size, overlap,
                                              separators[separators.index(sep) + 1:]))
                current = ""
            else:
                current = (chunks[-1][-overlap:] + sep + piece) if chunks else piece
    if current:
        chunks.append(current)
    return [c for c in chunks if c.strip()]


# ---------- 2. Structure-aware: respect the author's headings ----
def markdown_chunk(text, max_size=1200):
    """Split on headings and carry the heading path into each chunk.
    A chunk that says 'Refunds > Eligibility' matches far better
    than an anonymous paragraph."""
    sections, path, buffer = [], [], []

    def flush():
        if buffer:
            body = "\n".join(buffer).strip()
            if body:
                sections.append({"heading_path": " > ".join(path),
                                 "text": " > ".join(path) + "\n\n" + body})

    for line in text.split("\n"):
        m = re.match(r"^(#{1,6})\s+(.*)", line)
        if m:
            flush(); buffer = []
            level = len(m.group(1))
            path = path[:level - 1] + [m.group(2).strip()]
        else:
            buffer.append(line)
    flush()

    # Split any oversized section, keeping its heading path
    out = []
    for s in sections:
        if len(s["text"]) <= max_size:
            out.append(s)
        else:
            for piece in recursive_chunk(s["text"], max_size, 100):
                out.append({"heading_path": s["heading_path"], "text": piece})
    return out


# ---------- 3. Semantic: split where the topic changes -----------
def semantic_chunk(text, embed_fn, percentile=90, max_size=2000):
    """Embed each sentence, measure similarity between neighbours,
    and cut where similarity drops sharply -- i.e. where the
    subject changes."""
    sentences = [s.strip() for s in re.split(r"(?<=[.!?])\s+", text) if s.strip()]
    if len(sentences) < 3:
        return [text]

    vectors = np.array(embed_fn(sentences))
    vectors /= np.linalg.norm(vectors, axis=1, keepdims=True)

    # distance between each consecutive pair
    distances = 1 - (vectors[:-1] * vectors[1:]).sum(axis=1)

    # A relative threshold adapts to the document; an absolute one
    # would need retuning for every corpus.
    threshold = np.percentile(distances, percentile)
    breakpoints = [i + 1 for i, d in enumerate(distances) if d > threshold]

    chunks, start = [], 0
    for bp in breakpoints + [len(sentences)]:
        chunk = " ".join(sentences[start:bp])
        chunks.extend(recursive_chunk(chunk, max_size, 100)
                      if len(chunk) > max_size else [chunk])
        start = bp
    return [c for c in chunks if c.strip()]

The two techniques that actually move the numbers

PythonParent-document and contextual retrieval
# ---------- Parent-document: index small, return large -----------
# Small chunks embed precisely. Large chunks give the model context.
# Decouple them and you get both.

def build_parent_child(document, parent_size=3000, child_size=400):
    parents = recursive_chunk(document, parent_size, 200)
    records = []
    for p_idx, parent in enumerate(parents):
        for child in recursive_chunk(parent, child_size, 50):
            records.append({
                "embed_text": child,      # what goes in the vector index
                "return_text": parent,    # what the model actually sees
                "parent_id": p_idx,
            })
    return records

def retrieve_parents(index, query, embed_fn, k=4):
    hits = search(index, query, embed_fn, k=k * 3)
    seen, out = set(), []
    for hit in hits:                       # deduplicate: several children
        pid = hit["parent_id"]             # often share one parent
        if pid not in seen:
            seen.add(pid)
            out.append(hit["return_text"])
        if len(out) == k:
            break
    return out


# ---------- Contextual retrieval ---------------------------------
# A chunk saying "the limit is 30 days" is unretrievable -- what
# limit? Prepend LLM-written context and it becomes findable.

CONTEXT_PROMPT = """<document>
{document}
</document>

Here is a chunk from that document:
<chunk>
{chunk}
</chunk>

Give a short (1-2 sentence) context situating this chunk within the
document, to improve search retrieval. Answer with the context only."""

def contextualise(document, chunks, chat_fn):
    out = []
    for chunk in chunks:
        # The full document is a stable PREFIX across every chunk of
        # this document -- so prompt caching makes this far cheaper
        # than it looks. Order matters: document first, chunk last.
        context = chat_fn(CONTEXT_PROMPT.format(document=document, chunk=chunk))
        out.append({"embed_text": f"{context}\n\n{chunk}",
                    "return_text": chunk,
                    "context": context})
    return out

# Reported recall improvements from this technique are large --
# frequently the single biggest ingestion-side win available.
# Combine with BM25 over the same contextualised text for more.

Section 04 AdvancedA production pipeline

JavaIncremental, idempotent ingestion
@Service
class IngestionPipeline {

    private final VectorStore vectorStore;
    private final DocumentStateRepository state;
    private final EmbeddingCache cache;

    @Transactional
    public IngestResult ingest(Resource resource, long tenantId, String documentId) {

        // 1. CHANGE DETECTION -- skip unchanged documents entirely.
        //    Re-embedding an unchanged corpus nightly is the most
        //    common source of wasted spend in RAG systems.
        String hash = sha256(resource);
        if (state.findByDocumentId(documentId)
                 .map(s -> s.contentHash().equals(hash)).orElse(false)) {
            return IngestResult.unchanged(documentId);
        }

        // 2. PARSE, with validation
        List<Document> docs = new TikaDocumentReader(resource).get();
        String text = docs.stream().map(Document::getText)
                          .collect(Collectors.joining("\n\n"));
        if (text.strip().length() < 100) {
            // Almost certainly a scan. Route to OCR rather than
            // silently indexing an empty document.
            throw new UnparseableDocumentException(documentId);
        }

        // 3. CLEAN -- strip headers/footers repeating across pages
        text = cleaner.stripRepeatedLines(text);

        // 4. CHUNK
        List<Document> chunks = TokenTextSplitter.builder()
                .withChunkSize(700).withMinChunkSizeChars(350).build()
                .apply(List.of(new Document(text)));

        // 5. ENRICH -- capture now what you cannot recover later
        for (int i = 0; i < chunks.size(); i++) {
            chunks.get(i).getMetadata().putAll(Map.of(
                    "tenant_id", tenantId, "document_id", documentId,
                    "chunk_index", i, "source", resource.getFilename(),
                    "content_hash", hash,
                    "ingested_at", Instant.now().toString()));
        }

        // 6. DELETE THEN INSERT. Without the delete, stale chunks
        //    from the previous version stay and compete with the new.
        vectorStore.delete("document_id == '" + documentId + "'");
        vectorStore.add(chunks);

        state.save(new DocumentState(documentId, hash, chunks.size(), Instant.now()));
        return IngestResult.ingested(documentId, chunks.size());
    }
}
Make it event-driven

Ingestion is embarrassingly parallel, latency-tolerant and failure-prone — the exact profile for a message-driven pipeline. Document lands in object storage → event to Kafka → parsing consumer → chunking consumer → embedding consumer (batching aggressively) → store. Each stage scales independently, retries independently, and a poison document lands in a dead-letter queue instead of stalling the batch. This is §5.4, and your existing Kafka experience applies directly.

The metadata you cannot add later

Page number, section heading, document title, author, effective date, source URI, tenant, permission tags. Once a chunk is a bare string in a table, none of these are recoverable without re-parsing every document. Capture them during parsing, even if you have no immediate use — you will need them for citations, for filtering, and for the "why did it return this?" question that arrives the first week after launch.

Section 06 ProfessionalExercises

Do these — roughly a weekend
  1. Parse ten of your own PDFs and read the extracted text. Count how many have column, table or header problems. This number will surprise you.
  2. Implement recursive_chunk and compare its boundaries against fixed-size chunking on the same document. Look at where each cuts.
  3. Implement markdown_chunk with heading paths. Measure recall with and without the heading prefix — it is usually a free win.
  4. Implement semantic chunking. Plot the sentence-to-sentence distance curve for one document and see whether the breakpoints match where you would have split it.
  5. Build parent-document retrieval. Compare answer quality against flat chunking at the same index size.
  6. Implement contextual retrieval on 100 chunks. Measure recall before and after, and measure the ingestion cost with and without prompt caching.
  7. Run the full parameter sweep. Plot recall@20 against chunk size for each strategy and pick your operating point from the chart.
  8. Build change detection with content hashing. Re-run ingestion on an unchanged corpus and confirm zero embedding calls.
