Reinforcement Learning

Learning by trial and reward. This page explains the reinforcement-learning loop — an agent taking actions in an environment to maximise reward — the core concepts (state, action, policy, value), the main approaches, and the reason it matters most to you: RLHF, the technique that turned raw language models into helpful assistants.

Section 01 BeginnerStart from zero

Assumed knowledge

The learning paradigms (Topic 2.3) and how LLMs are trained (Topic 1.3). RL is the third paradigm, and the one behind alignment.

Supervised learning learns from labelled answers; unsupervised learning finds structure. Reinforcement learning is different from both: an agent learns by doing — taking actions in an environment, receiving rewards or penalties, and adjusting to earn more reward over time. It is how you learn to ride a bike: not from labelled examples, but from trying, falling, and gradually finding what works.

The reinforcement-learning loop

An agent observes the state of an environment, takes an action, and receives a reward plus a new state. It repeats, learning a policy — a strategy for choosing actions — that maximises total reward over time. The hard part is that rewards can be delayed: a move in chess might only pay off twenty moves later, so the agent must learn to credit actions for consequences that come much later. That "credit assignment over time" is what makes RL both powerful and difficult.

The words, in plain English
Agent
The learner and decision-maker.
Environment
The world the agent acts in.
State
The current situation the agent observes.
Action
A choice the agent can make.
Reward
The feedback signal — higher is better.
Policy
The agent's strategy: which action to take in each state.
Value
How good a state (or action) is, counting future rewards.

Actor-criticCombine both — a policy (actor) and a value estimate (critic)A2C, PPO
Model-basedLearn a model of the environment and plan with itMuZero

The exploration-exploitation dilemma is at the heart of RL. Should the agent exploit what it knows works, or explore new actions that might work better? Too much exploitation and it gets stuck in a mediocre habit; too much exploration and it never settles. Every RL method balances these. The same tension appears in product decisions (A/B testing) and even in LLM sampling temperature (Topic 1.2) — explore-vs-exploit is a general principle, not just an RL curiosity.

Section 03 AdvancedRLHF: the RL that matters to you

You may never train a game-playing agent, but you use the product of reinforcement learning every day. RLHF — Reinforcement Learning from Human Feedback — is what turned raw language models into helpful, aligned assistants (Topic 1.3).

How RLHF works

A pre-trained language model can continue text but is not reliably helpful, honest or safe. RLHF fixes this using RL, with a clever twist on "reward":

  1. Collect human preferences. Show people pairs of model responses; they pick the better one.
  2. Train a reward model. A model learns to predict which responses humans prefer — turning fuzzy "helpfulness" into a numeric reward signal.
  3. Optimise the LLM with RL. Using PPO (the actor-critic method from Section 02), adjust the language model to produce responses the reward model scores highly — while a penalty keeps it from drifting too far from the original model (Topic 1.2, KL divergence).

The result is a model tuned toward what humans actually want. The reward is human preference; the optimiser is reinforcement learning.

The frontier: alternatives to full RLHF. RLHF is powerful but complex — training a separate reward model and running PPO is finicky. DPO (Direct Preference Optimization) reaches a similar result by optimising directly on the preference pairs, skipping the reward model and the RL loop entirely — simpler and now widely used (Topic 3.5). Constitutional AI uses a written set of principles and model-generated critiques to reduce the human-labelling burden. And reinforcement learning on verifiable rewards — rewarding correct answers to maths and code — is how reasoning models are trained (Topic 9.4). RL, in various forms, is central to how modern models are aligned and made to reason.

Section 04 ProfessionalThe honest reality of RL

RL is powerful and notoriously hard

Reinforcement learning has a deserved reputation for being difficult and finicky. It is sample-inefficient (needs enormous amounts of trial and error), unstable (small changes can break training), and reward-hacking-prone (agents find loopholes that maximise the reward without doing what you intended — a boat-racing agent that spins in circles collecting points instead of finishing the race). Reward design is genuinely hard: the agent optimises exactly what you reward, not what you meant. For most business problems, supervised learning or a simpler method is the right tool; RL earns its complexity in sequential-decision problems where trial-and-error learning is truly needed — games, control, and alignment.

What to actually know

Unless you specialise in it, you do not need to implement PPO. What you do need: understand the RL loop (state-action-reward-policy) well enough to reason about agents and alignment; understand RLHF and its alternatives (DPO, Constitutional AI) so you can read model documentation and understand why models behave as they do; and recognise reward hacking as a failure mode. This conceptual fluency is what makes the training and alignment sections of any model's documentation legible to you — and it connects directly to how the LLMs you build with were made helpful (Topic 1.3) and how reasoning models are trained (Topic 9.4).

Section 05 ProfessionalExercises

Do these — roughly a weekend
  1. Implement tabular Q-learning for a simple grid-world. Watch the agent learn a path to the goal through trial and error.
  2. Adjust the exploration rate. Show that too little exploration traps the agent in a suboptimal path.
  3. Use Gymnasium to train a simple agent (CartPole) with a library PPO implementation. Watch the reward curve climb.
  4. Design a reward function badly on purpose and observe reward hacking — the agent gaming your metric.
  5. Read the InstructGPT paper's RLHF section. Explain the three steps of Section 03 in your own words.
  6. Compare RLHF and DPO conceptually. Why is DPO simpler, and what does it give up?
