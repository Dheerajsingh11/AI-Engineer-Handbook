Machine learning is a different way of writing programs. In ordinary programming you write the rules and the computer applies them to data. In machine learning you supply the data and the answers, and the computer works out the rules.

Two ways to build a spam filter
Traditional programmingMachine learning
You provideRules: "if it contains 'viagra', flag it"10,000 emails labelled spam or not
Computer providesThe verdict on each emailThe rules — as learned numbers
AdaptingYou write more rules, foreverAdd more labelled examples, retrain
Fails whenSpammers change tacticsNew spam looks nothing like the training data
Why this is in an AI engineering roadmap

You will not train models like these in your job. You are here for three other reasons, and they are worth being explicit about.

  • The evaluation discipline is identical. Train/test splits, leakage, overfitting, confidence intervals — all of it applies unchanged to LLM evals, where it is far less commonly practised and therefore far more valuable.
  • These algorithms are inside your RAG pipeline. k-means is the IVF vector index. k-NN is vector search. Logistic regression is how you build a query router.
  • Often it is simply the right answer. Classifying support tickets into six categories does not need an LLM. Gradient boosting on 5,000 labelled examples will be more accurate, a thousand times cheaper, and deterministic.
The words, in plain English
Feature
One input column. "Number of exclamation marks" is a feature of an email.
Label / target
The answer you are trying to predict. Spam or not; the house price.
Training
The process of finding the numbers that make predictions accurate.
Model
The learned numbers, plus the rule for using them.
Classification / regression
Predicting a category vs predicting a number.
Overfitting
Memorising the training data instead of learning the pattern. Perfect on data you have seen, useless on data you have not.
Generalisation
Performing well on data never seen during training. The only thing that matters.
Hyperparameter
A setting you choose rather than learn: learning rate, tree depth, number of clusters.

Section 03 IntermediateLinear regression, derived twice

Fit a straight line: ŷ = Xw + b. Choose w and b to minimise squared error. Two routes to the answer, and it is instructive that they agree.

Mean squared error L(w)  =  1n Σi (yi − xiTw)2 Why squared rather than absolute error? Three reasons: it is differentiable everywhere (absolute value is not, at zero), it penalises large errors disproportionately, and it has a closed-form solution. The cost is sensitivity to outliers — which is exactly when you switch to MAE or Huber loss.
Route 1 — the closed form (normal equations)
  1. L(w) = (y − Xw)T(y − Xw) Squared error in matrix form, dropping the 1/n which does not affect the minimiser.
  2. = yTy − 2wTXTy + wTXTXw Expand. The two cross terms are scalars and equal, hence the 2.
  3. ∇wL = −2XTy + 2XTXw Differentiate with respect to w.
  4. Set to zero: XTXw = XTy The minimum is where the gradient vanishes. These are the normal equations.
  5. w = (XTX)−1XTy   ■ Exact, in one step. Costs O(d3) to invert, so it is impractical past a few thousand features — which is why route 2 exists.
PythonBoth routes, from scratch, compared
import numpy as np

def fit_closed_form(X, y):
    X = np.c_[np.ones(len(X)), X]                # prepend a bias column
    # lstsq, not inv(): numerically stable when X'X is near-singular
    w, *_ = np.linalg.lstsq(X, y, rcond=None)
    return w

def fit_gradient_descent(X, y, lr=0.05, epochs=2000):
    X = np.c_[np.ones(len(X)), X]
    n, d = X.shape
    w = np.zeros(d)
    for _ in range(epochs):
        pred = X @ w
        # gradient of MSE: (2/n) X'(Xw - y)
        grad = (2 / n) * X.T @ (pred - y)
        w -= lr * grad
    return w

rng = np.random.default_rng(0)
X = rng.normal(size=(500, 3))
true_w = np.array([4.0, -2.0, 0.5, 3.0])         # bias + 3 weights
y = np.c_[np.ones(500), X] @ true_w + rng.normal(0, 0.3, 500)

print("closed form:", fit_closed_form(X, y).round(3))
print("grad descent:", fit_gradient_descent(X, y).round(3))
print("truth       :", true_w)
# closed form:  [ 4.008 -2.013  0.494  2.998]
# grad descent: [ 4.008 -2.013  0.494  2.998]   same answer

Regularisation, and what L1 versus L2 actually does

Ridge (L2) and Lasso (L1) Ridge: L + λΣwj2  Lasso: L + λΣ|wj| Both add a penalty for large weights, discouraging the model from fitting noise. The difference in behaviour comes from the derivative. Ridge's penalty gradient is 2λw — it shrinks in proportion to the weight, so small weights are barely touched and never quite reach zero. Lasso's is λ·sign(w) — a constant pull regardless of size, which pushes small weights all the way to exactly zero. That is why Lasso performs feature selection and Ridge does not.

Section 04 IntermediateLogistic regression, and why cross-entropy

For classification you need a probability, not an unbounded number. Push the linear output through a sigmoid and it lands in (0,1). But that raises a question people rarely ask: why not just use squared error on the probability?

Why cross-entropy is the right loss for classification
  1. Model: p = σ(xTw), where σ(z) = 1/(1+e−z) A probability that the label is 1.
  2. Likelihood of one example: py(1−p)1−y A neat trick: for y=1 this is p; for y=0 it is 1−p.
  3. Log-likelihood over the dataset: Σ [y log p + (1−y) log(1−p)] Take logs so products become sums — numerically stable, as in Topic 1.2.
  4. Loss = negative of that. This is binary cross-entropy. Maximising likelihood equals minimising cross-entropy. The loss was not invented; it was derived.
  5. ∇wL = XT(p − y) / n The remarkable part: the sigmoid derivative cancels perfectly, leaving the same clean form as linear regression. Prediction minus truth, times input.
Why not squared error on probabilities

Because of the gradient. When the model is confidently wrong — predicting 0.001 for something that is actually 1 — squared error's gradient is tiny, because it gets multiplied by the sigmoid's derivative, which is near zero out there. The model barely learns from its worst mistakes. Cross-entropy's gradient in that case is large, precisely because the log blows up. Cross-entropy punishes confident errors; squared error shrugs at them. That is the whole reason it is the standard.

PythonLogistic regression from scratch
import numpy as np

def sigmoid(z):
    # Split by sign to avoid exp() overflow on large |z|
    out = np.empty_like(z, dtype=float)
    pos, neg = z >= 0, z < 0
    out[pos] = 1 / (1 + np.exp(-z[pos]))
    ez = np.exp(z[neg])
    out[neg] = ez / (1 + ez)
    return out

def fit_logistic(X, y, lr=0.1, epochs=3000, l2=0.0):
    X = np.c_[np.ones(len(X)), X]
    w = np.zeros(X.shape[1])
    n = len(y)
    for _ in range(epochs):
        p = sigmoid(X @ w)
        grad = X.T @ (p - y) / n                  # line (5) of the derivation
        grad[1:] += l2 * w[1:]                    # never regularise the bias
        w -= lr * grad
    return w

def predict_proba(X, w):
    return sigmoid(np.c_[np.ones(len(X)), X] @ w)

rng = np.random.default_rng(0)
X = np.vstack([rng.normal(-1, 1, (300, 2)), rng.normal(1.5, 1, (300, 2))])
y = np.r_[np.zeros(300), np.ones(300)]

w = fit_logistic(X, y)
acc = ((predict_proba(X, w) > 0.5) == y).mean()
print(f"accuracy {acc:.3f}")                      # ~0.94

# The threshold is YOURS to choose, not fixed at 0.5.
# Lower it to raise recall; raise it to raise precision.
for t in (0.3, 0.5, 0.7):
    pred = predict_proba(X, w) > t
    tp = ((pred == 1) & (y == 1)).sum()
    print(f"t={t}  precision {tp/max(pred.sum(),1):.3f}  recall {tp/(y==1).sum():.3f}")

Section 05 AdvancedDecision trees, and why entropy

A tree asks yes/no questions about features and splits the data. The only real question is which question to ask at each node. The answer: the one that most reduces uncertainty about the label — which brings entropy from Topic 1.2 back with a concrete job.

Information gain Gain = H(parent) − Σchildren ncn H(child) Uncertainty before the split, minus the weighted average uncertainty after. Try every feature and every threshold, and take the split with the largest gain. Gini impurity 1−Σpi2 is the common alternative — it avoids computing logarithms, gives near-identical trees, and is scikit-learn's default.
PythonA decision tree in 50 lines
import numpy as np
from collections import Counter

def entropy(y):
    if len(y) == 0:
        return 0.0
    counts = np.bincount(y.astype(int))
    p = counts[counts > 0] / len(y)
    return float(-(p * np.log2(p)).sum())

def best_split(X, y):
    n, d = X.shape
    parent_h = entropy(y)
    best = (0.0, None, None)                     # gain, feature, threshold
    for feature in range(d):
        # Candidate thresholds: midpoints between sorted unique values
        values = np.unique(X[:, feature])
        for thr in (values[:-1] + values[1:]) / 2:
            left = X[:, feature] <= thr
            if left.sum() == 0 or left.sum() == n:
                continue
            gain = parent_h - (left.mean() * entropy(y[left])
                               + (1 - left.mean()) * entropy(y[~left]))
            if gain > best[0]:
                best = (gain, feature, float(thr))
    return best

class Node:
    def __init__(self, prediction=None, feature=None, thr=None, left=None, right=None):
        self.prediction, self.feature, self.thr = prediction, feature, thr
        self.left, self.right = left, right

def build_tree(X, y, depth=0, max_depth=5, min_samples=5):
    # Stopping rules ARE the regularisation. Without them the tree
    # grows until every leaf holds one sample -- perfect on training
    # data, useless on anything else.
    if (depth >= max_depth or len(y) < min_samples or len(set(y)) == 1):
        return Node(prediction=Counter(y).most_common(1)[0][0])

    gain, feature, thr = best_split(X, y)
    if feature is None or gain <= 1e-9:
        return Node(prediction=Counter(y).most_common(1)[0][0])

    mask = X[:, feature] <= thr
    return Node(feature=feature, thr=thr,
                left =build_tree(X[mask],  y[mask],  depth+1, max_depth, min_samples),
                right=build_tree(X[~mask], y[~mask], depth+1, max_depth, min_samples))

def predict_one(node, x):
    while node.prediction is None:
        node = node.left if x[node.feature] <= node.thr else node.right
    return node.prediction

def show(node, depth=0, names=None):
    pad = "  " * depth
    if node.prediction is not None:
        print(f"{pad}-> class {node.prediction}")
    else:
        name = names[node.feature] if names else f"f{node.feature}"
        print(f"{pad}if {name} <= {node.thr:.3f}:")
        show(node.left, depth + 1, names)
        print(f"{pad}else:")
        show(node.right, depth + 1, names)

# A tree is the only model that prints its own rules -- which is
# why it is still chosen where a decision must be explained.

Section 06 Advancedk-means — and why it is your vector index

Worth building carefully, because IVF indexes in §4.3 are k-means applied to embeddings. Cluster the vectors, then at query time search only the nearest few clusters instead of everything.

  1. Initialise k centroids. Random points is poor; k-means++ picks them spread apart and converges far more reliably.
  2. Assign every point to its nearest centroid.
  3. Update each centroid to the mean of its assigned points.
  4. Repeat 2–3 until assignments stop changing. Guaranteed to converge, but only to a local optimum — so run it several times and keep the best.
Pythonk-means with k-means++ initialisation
import numpy as np

def kmeans_plusplus(X, k, rng):
    """Pick centroids far apart: each new one is chosen with
    probability proportional to squared distance from the nearest
    existing centroid. This is what makes k-means reliable."""
    centroids = [X[rng.integers(len(X))]]
    for _ in range(1, k):
        d2 = np.min(((X[:, None, :] - np.array(centroids)[None]) ** 2).sum(-1), axis=1)
        probs = d2 / d2.sum()
        centroids.append(X[rng.choice(len(X), p=probs)])
    return np.array(centroids)

def kmeans(X, k=8, iters=100, n_init=5, seed=0):
    rng = np.random.default_rng(seed)
    best_inertia, best = np.inf, None

    for _ in range(n_init):                       # restarts escape bad local optima
        C = kmeans_plusplus(X, k, rng)
        labels = np.zeros(len(X), dtype=int)
        for _ in range(iters):
            # assign: ||x-c||^2 = ||x||^2 - 2x.c + ||c||^2
            # ||x||^2 is constant per row, so it cannot change the argmin
            d = -2 * X @ C.T + (C ** 2).sum(1)
            new_labels = d.argmin(1)
            if np.array_equal(new_labels, labels):
                break                             # converged
            labels = new_labels
            for j in range(k):
                members = X[labels == j]
                if len(members):
                    C[j] = members.mean(0)
        inertia = float(((X - C[labels]) ** 2).sum())
        if inertia < best_inertia:
            best_inertia, best = inertia, (C.copy(), labels.copy())
    return (*best, best_inertia)

# --- this is an IVF index -----------------------------------------
rng = np.random.default_rng(0)
store = rng.normal(size=(50_000, 128))
store /= np.linalg.norm(store, axis=1, keepdims=True)

C, labels, _ = kmeans(store, k=224)               # ~sqrt(n) clusters

def ivf_search(query, n_probe=8, k=10):
    """Search only the n_probe nearest clusters."""
    nearest_clusters = np.argsort(-(C @ query))[:n_probe]
    candidate_ids = np.flatnonzero(np.isin(labels, nearest_clusters))
    scores = store[candidate_ids] @ query
    top = np.argsort(-scores)[:k]
    return candidate_ids[top], len(candidate_ids)

q = store[42]
ids, scanned = ivf_search(q)
print(f"scanned {scanned} of {len(store)} vectors ({scanned/len(store):.1%})")
# scanned 1837 of 50000 vectors (3.7%)  -- 27x less work

exact = np.argsort(-(store @ q))[:10]
print(f"recall@10 = {len(set(ids) & set(exact)) / 10:.1f}")   # 0.9
You have just built an approximate nearest neighbour index

Scanning 3.7% of the data and still retrieving 9 of the correct top 10 is the entire bargain of ANN search. Raising n_probe increases recall and cost; lowering it does the reverse. That single dial is the same trade-off as ef_search in HNSW, and now you have implemented the mechanism behind it rather than just configured it.

Section 07 ProfessionalThe workflow discipline

This section matters more than any algorithm above, and it is the part that transfers directly to LLM evaluation.

  1. Split before you look. Train / validation / test, typically 60/20/20. The test set is opened once, at the very end. Every time you peek and adjust, you leak a little information into your model choices.
  2. Split correctly for your data. Random splits are wrong for time series (you would train on the future) and wrong when rows are grouped (all of one customer's rows must land in one fold, or the model recognises the customer rather than the pattern).
  3. Fit preprocessing inside the fold. Fitting a scaler on all the data before splitting leaks test statistics into training. Use a Pipeline and this becomes impossible by construction.
  4. Establish a dumb baseline. Majority class, or a simple heuristic. If your model does not clearly beat it, you have learned something important.
  5. Cross-validate for reliable estimates on small data. Stratified k-fold for imbalanced classes; time-series split for temporal data; group k-fold for clustered rows.
  6. Report an interval, not a point. "84% ± 3%" is a result. "84%" is a number that might be noise.
PythonA leak-proof pipeline with honest evaluation
from sklearn.pipeline import Pipeline
from sklearn.compose import ColumnTransformer
from sklearn.preprocessing import StandardScaler, OneHotEncoder
from sklearn.impute import SimpleImputer
from sklearn.ensemble import HistGradientBoostingClassifier
from sklearn.model_selection import StratifiedKFold, cross_val_score
from sklearn.metrics import classification_report
import numpy as np

numeric = ["age", "tenure_months", "monthly_spend"]
categorical = ["plan", "region"]

pre = ColumnTransformer([
    ("num", Pipeline([("impute", SimpleImputer(strategy="median")),
                      ("scale",  StandardScaler())]), numeric),
    ("cat", OneHotEncoder(handle_unknown="ignore"), categorical),
])

pipe = Pipeline([("pre", pre),
                 ("clf", HistGradientBoostingClassifier(random_state=0))])

# Every transformer is fitted separately inside each fold.
# No test-set statistic can reach the training data.
cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=0)

Data leakage — the failure that looks like success

Leakage is when information unavailable at prediction time reaches the model during training. The symptom is always the same: excellent offline metrics, useless in production. The common forms are worth memorising because each looks innocent:

  • Scaling or imputing before splitting — test statistics influence training.
  • A feature computed after the outcome. days_since_last_login is null exactly for customers who churned.
  • Duplicate rows spanning the split — the model has literally seen the test data.
  • Tuning hyperparameters against the test set, then reporting the test score.
  • Target encoding without doing it inside the fold.

The check that catches most of it: if your model is surprisingly good, assume leakage and go looking, rather than celebrating.

Section 08 ProfessionalExercises

Do these — roughly a weekend
  1. Implement linear regression both ways and confirm they agree. Then add 5,000 features and watch the closed form become slow while gradient descent does not.
  2. Fit Ridge and Lasso across a sweep of λ and plot each coefficient against λ. Watch Lasso's coefficients hit exactly zero and Ridge's merely shrink.
  3. Implement logistic regression from scratch and check it against scikit-learn's coefficients.
  4. Build the decision tree and print it on the Iris dataset. Set max_depth=None and observe perfect training accuracy with worse test accuracy — overfitting, visible.
  5. Run the k-means IVF experiment. Plot recall@10 against n_probe from 1 to 50. Keep this plot; it is the same curve you will tune in §4.3.
  6. Deliberately introduce leakage: fit StandardScaler on all data before splitting. Measure how much the cross-validation score inflates.
  7. Enter one Kaggle Playground competition. Establish a baseline, then improve it three times. Note which improvements survived cross-validation and which were noise.
