14.5

Time Series Forecasting

Predicting what comes next in time. This page covers forecasting — what makes time-ordered data special, the classic methods (moving averages, ARIMA, exponential smoothing) and the ML/deep approaches, the features that carry the signal, and the one rule you must never break: never let the future leak into the past.

Section 01 BeginnerStart from zero

Assumed knowledge

Classical ML (Topic 2.3) and feature engineering (Topic 14.1). Time series adds one crucial constraint: order.

Sales per day, server load per minute, a stock price, temperature readings — time-series data is a sequence of measurements ordered in time, and the goal is usually forecasting: predicting future values from past ones. It is one of the most common and commercially valuable ML problems, and it comes with rules that ordinary ML ignores.

What makes time series special

In ordinary ML you can shuffle your data freely. In time series you cannot — order is the whole point. Three properties follow. Autocorrelation: a value depends on recent values (today's temperature is close to yesterday's). Trend: a long-term direction (sales growing over years). Seasonality: repeating cycles (more ice cream in summer, more traffic on weekdays). A good forecast captures all three — and, critically, you may only ever use the past to predict the future, never the reverse.

The words, in plain English
Forecasting
Predicting future values of a time series.
Trend
The long-term direction (up, down, flat).
Seasonality
Regular repeating patterns (daily, weekly, yearly).
Autocorrelation
A value's dependence on its own recent past.
Stationary
A series whose statistics do not change over time — easier to model.
Lag
A past value used as a feature (yesterday's value, last week's).

Always start with a naive baseline

Before any fancy model, compute the naive forecast: "tomorrow equals today," or the seasonal version "this Monday equals last Monday." It is astonishing how often a complex model fails to beat this. The naive baseline is your reality check — if your gradient-boosted, feature-rich model cannot outperform "same as last week," something is wrong (or the series is genuinely unpredictable). Report your model's improvement over the naive baseline, not its raw error, so you know whether the sophistication earned its keep.

Section 03 IntermediateTurning a time series into a supervised problem

The modern ML approach reframes forecasting as ordinary regression: create features from the past, predict the next value. The features are where the signal lives.

PythonTime-series feature engineering
import pandas as pd

# LAGS: past values as features (autocorrelation, Section 01).
df["lag_1"]  = df["sales"].shift(1)          # yesterday
df["lag_7"]  = df["sales"].shift(7)          # same day last week (seasonality)

# ROLLING WINDOWS: recent trend and volatility.
df["roll_mean_7"] = df["sales"].shift(1).rolling(7).mean()
df["roll_std_7"]  = df["sales"].shift(1).rolling(7).std()

# CALENDAR features: capture seasonality explicitly.
df["dayofweek"] = df["date"].dt.dayofweek
df["month"]     = df["date"].dt.month
df["is_holiday"] = df["date"].isin(holidays)

# CRITICAL: every feature uses only PAST data (note the shift(1)).
# A rolling mean that includes today would leak the answer.
# Now predict df["sales"] from these -- gradient boosting works well.

Section 04 AdvancedThe one rule: never leak the future

Validation must respect time

The single most important thing in time-series ML: you must never use future data to predict the past. Ordinary random train/test splits (Topic 2.3) do exactly that — they put some future days in training and some past days in test, so the model "predicts" yesterday having seen tomorrow. The result is a beautiful offline score and a useless production model. Instead use time-based splits: train on the earliest data, validate on the next period, always past → future. For robustness, use walk-forward validation: train on months 1–3, test on month 4; then train on 1–4, test on 5; and so on. This mimics how the model will actually be used.

PythonTime-aware validation
from sklearn.model_selection import TimeSeriesSplit

# Each fold trains on the PAST, tests on the FUTURE. Never shuffles.
tscv = TimeSeriesSplit(n_splits=5)
for train_idx, test_idx in tscv.split(X):
    # train_idx is always entirely before test_idx in time.
    model.fit(X[train_idx], y[train_idx])
    score(model, X[test_idx], y[test_idx])

# A plain KFold or train_test_split here would leak the future and
# give you a score you cannot reproduce in production (Topic 2.3).

Section 05 ProfessionalChoosing an approach, and the LLM angle

Which method when
SituationReach for
A few series, want interpretabilityARIMA or exponential smoothing
Business series with holidays/seasonalityProphet
Many series, extra features availableGradient boosting on lag features (Section 03)
Huge data, complex non-linear patternsDeep learning (LSTM, temporal transformer)
Need probabilistic / uncertainty intervalsProphet, or quantile models

Forecasting rarely needs LLMs — and this is worth stating because the instinct to reach for an LLM is strong. Numeric time-series forecasting is a domain where classical statistics and gradient boosting comfortably beat language models; an LLM is the wrong tool for "predict next month's sales from twelve months of numbers." (There is active research on foundation models for time series, which is different from using a chat LLM.) Where an LLM does help is the surrounding work: explaining a forecast in plain language, extracting events from text that affect the series, or building a natural-language interface over a forecasting system. Match the tool to the task — numbers to numeric models, language to language models.

Section 06 ProfessionalExercises

Do these — roughly a weekend
  1. Plot a real time series and identify its trend and seasonality by eye. Decompose it with statsmodels to confirm.
  2. Compute the naive and seasonal-naive baselines. These are the numbers every model must beat.
  3. Build lag and rolling-window features and forecast with gradient boosting. Beat the baselines.
  4. Compare against Prophet and ARIMA on the same series. Note interpretability vs accuracy.
  5. Deliberately use a random train/test split and observe an inflated score. Then switch to TimeSeriesSplit and see the honest one.
  6. Implement walk-forward validation and report your model's improvement over the naive baseline at each step.
