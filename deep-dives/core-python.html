Section 01 BeginnerStart from zero

Assumed knowledge

You can program in some language. This page is written for a Java developer, but any C-family background works. If you have never programmed at all, work through the Kaggle Python course in Section 09 first, then come back — this page will still be useful.

Python's reputation as "easy" causes a specific problem for experienced developers: they learn the syntax in a weekend, write Java in Python for two years, and never find out why anyone likes the language. This page is about the second part.

The one model to internalise

In Java, a variable is a box that holds a value. int x = 5 allocates space and puts 5 in it. Assignment copies into the box.

In Python, a variable is a label tied to an object floating in memory. x = 5 creates an integer object and attaches the name x to it. Assignment re-attaches the label. Nothing is copied.

PythonWhy this matters immediately
a = [1, 2, 3]
b = a                 # NOT a copy -- b is a second label on the same list
b.append(4)
print(a)              # [1, 2, 3, 4]  -- surprising if you think "box"

b = a.copy()          # now it really is a separate list
b.append(5)
print(a)              # [1, 2, 3, 4]  -- unchanged

# The classic trap this causes:
def add_item(item, basket=[]):        # DANGER
    basket.append(item)
    return basket

print(add_item("apple"))   # ['apple']
print(add_item("pear"))    # ['apple', 'pear']  <- the SAME list, still there

# The default value is evaluated ONCE, when the function is defined.
# Correct version:
def add_item(item, basket=None):
    basket = [] if basket is None else basket
    basket.append(item)
    return basket
Java word → Python word
Package / JAR → Module / Package
A .py file is a module; a directory of them is a package. import executes the file the first time it is imported, and caches it.
Maven / Gradle → pip, uv, Poetry
No single blessed tool. Dependencies are declared in pyproject.toml. Use uv for new projects.
Classpath → Virtual environment
An isolated directory holding one project's dependencies. Without one, every project shares a single global install and they conflict. This is not optional.
Interface → Protocol / duck typing
Python does not check that you implement an interface. If your object has the right methods, it works. typing.Protocol lets a type-checker verify this statically.
record → @dataclass / Pydantic BaseModel
@dataclass generates __init__, __eq__ and __repr__. Pydantic adds runtime validation and JSON Schema, which is what LLM tool definitions need.
Stream → Comprehension / generator
[f(x) for x in xs if p(x)] replaces .stream().filter().map().toList(), and reads better.
Checked exception → (nothing)
All exceptions are unchecked. Nothing forces you to handle anything. Be deliberate at service boundaries.

Section 02 IntermediateThe data model — why Python is consistent

Python looks like it has many special syntaxes. It does not. Nearly every piece of syntax is sugar for calling a dunder (double-underscore) method, and once you know which, the language becomes predictable and extensible.

Syntax and the method it actually calls
You writePython callsImplement it to get
len(x)x.__len__()Your type works with len
x[k]x.__getitem__(k)Indexing and slicing
a + ba.__add__(b)Operator overloading — how NumPy works
for i in xx.__iter__()Your type becomes iterable
with x:x.__enter__() / __exit__()try-with-resources behaviour
x(...)x.__call__(...)An object that behaves like a function
str(x) / repr(x)__str__ / __repr__Readable output and useful debugging
a == ba.__eq__(b)Value equality (pair with __hash__)
await xx.__await__()Custom awaitables
Why this matters for AI work

This is why a @ b performs matrix multiplication on NumPy arrays — ndarray implements __matmul__. It is why a PyTorch Module is called like a function — it implements __call__. It is why the Value class in Topic 1.4 supports ordinary arithmetic. Libraries in this ecosystem lean heavily on the data model, and code that looks magical is usually just a dunder you have not met yet.

Section 03 IntermediateThe idioms that make Python worth using

PythonComprehensions, generators, unpacking
# --- comprehensions: the default way to transform a collection ---
scores = [0.9, 0.4, 0.7, 0.2]
passed = [s for s in scores if s > 0.5]                 # list
lookup = {f"doc{i}": s for i, s in enumerate(scores)}   # dict
unique = {round(s, 1) for s in scores}                  # set

# --- generators: lazy, constant memory ---------------------------
# Parentheses instead of brackets. Nothing is computed until asked.
big = (expensive(x) for x in range(10_000_000))
first_ten = [next(big) for _ in range(10)]   # only 10 calls happen

def read_chunks(path, size=8192):
    """Stream a file of any size in constant memory."""
    with open(path, encoding="utf-8") as f:
        while chunk := f.read(size):        # walrus: assign and test
            yield chunk

# --- unpacking ---------------------------------------------------
a, b = b, a                                 # swap, no temp variable
first, *rest = [1, 2, 3, 4]                 # first=1, rest=[2,3,4]
merged = {**defaults, **overrides}          # right-hand side wins

# --- enumerate and zip: never write an index loop -----------------
for i, (name, score) in enumerate(zip(names, scores), start=1):
    print(f"{i}. {name}: {score:.2f}")

# --- pattern matching (3.10+) -- like Java's switch expressions ---
def handle(event):
    match event:
        case {"type": "tool_call", "name": str(name), "args": dict(args)}:
            return dispatch(name, args)
        case {"type": "text", "content": content}:
            return content
        case _:
            raise ValueError(f"unknown event: {event}")
PythonDecorators and context managers, written not just used
import functools, time, contextlib

# A decorator is a function that wraps a function.
# @retry is sugar for: call_llm = retry(...)(call_llm)
def retry(times=3, backoff=1.0, exceptions=(Exception,)):
    def decorator(fn):
        @functools.wraps(fn)          # preserve __name__, docstring
        def wrapper(*args, **kwargs):
            last = None
            for attempt in range(times):
                try:
                    return fn(*args, **kwargs)
                except exceptions as e:
                    last = e
                    if attempt < times - 1:
                        time.sleep(backoff * (2 ** attempt))
            raise last
        return wrapper
    return decorator

@retry(times=4, backoff=0.5)
def call_llm(prompt): ...

# A context manager guarantees cleanup, like try-with-resources.
@contextlib.contextmanager
def timed(label):
    start = time.perf_counter()
    try:
        yield                          # the body of the `with` runs here
    finally:
        print(f"{label}: {time.perf_counter() - start:.3f}s")

with timed("embedding batch"):
    embed(documents)                   # timing printed even if this raises

Section 04 IntermediateTypes, dataclasses and Pydantic

Python's type hints are not enforced at runtime by the interpreter — they are annotations that tools read. Coming from Java this feels alarming; the resolution is to run a checker in CI so you get most of the guarantee back.

PythonThree levels of structure
from dataclasses import dataclass, field
from typing import Protocol, Literal
from pydantic import BaseModel, Field, field_validator

# 1. Type hints -- documentation that mypy/pyright can check
def top_k(scores: list[float], k: int = 5) -> list[int]:
    return sorted(range(len(scores)), key=lambda i: -scores[i])[:k]

# 2. dataclass -- Java's record. No validation.
@dataclass(frozen=True, slots=True)      # immutable + memory-efficient
class Chunk:
    text: str
    source: str
    page: int = 0
    metadata: dict = field(default_factory=dict)   # NOT metadata={}

# 3. Pydantic -- validates at runtime AND emits JSON Schema.
#    This is what LLM structured output and tool defs are built on.
class SearchQuery(BaseModel):
    query: str = Field(min_length=1, description="Natural language query")
    top_k: int = Field(default=5, ge=1, le=100)
    mode: Literal["dense", "sparse", "hybrid"] = "hybrid"

    @field_validator("query")
    @classmethod
    def strip_query(cls, v: str) -> str:
        return v.strip()

SearchQuery(query="  vector index  ", top_k=200)
# ValidationError: top_k -- Input should be less than or equal to 100

print(SearchQuery.model_json_schema())
# -> the exact JSON Schema you hand to a model for tool calling

# 4. Protocol -- structural typing. Any object with these methods
#    satisfies it; no inheritance or registration required.
class Retriever(Protocol):
    def search(self, query: str, k: int) -> list[Chunk]: ...
Mutable default arguments — twice

It is worth repeating because it is the single most common Python bug written by experienced developers from other languages. def f(x, items=[]) and @dataclass field metadata: dict = {} both create one object shared by every call or instance. Use None and construct inside, or field(default_factory=dict). Linters catch this — enable ruff and it will.

Section 05 AdvancedConcurrency: the GIL, threads and asyncio

Python has a Global Interpreter Lock: only one thread executes Python bytecode at a time. For CPU-bound work this makes threads useless. For AI work, though, almost everything is waiting on a network — and the GIL is released during I/O, so concurrency works fine. You just need the right tool.

Choosing a concurrency model
ApproachParallel?Use forJava analogue
asyncioNo, but concurrentMany API calls — the default for LLM workReactor / WebFlux
ThreadPoolExecutorNo (GIL)I/O with blocking libraries that have no async versionExecutorService
ProcessPoolExecutorYesCPU-bound work: parsing, chunking, local embeddingSeparate JVMs
NumPy / PyTorch opsYesArray maths — the C layer releases the GILNative code via JNI
PythonConcurrent LLM calls with bounded parallelism
import asyncio, random

async def embed_one(client, text, sem):
    # A semaphore bounds in-flight requests. Without it, 10,000
    # documents means 10,000 simultaneous calls and instant 429s.
    async with sem:
        for attempt in range(5):
            try:
                return await client.embed(text)
            except RateLimitError:
                # exponential backoff WITH jitter -- without jitter,
                # every retry fires at the same instant and re-limits.
                await asyncio.sleep(2 ** attempt + random.random())
        raise RuntimeError("exhausted retries")

async def embed_all(client, texts, concurrency=10):
    sem = asyncio.Semaphore(concurrency)
    tasks = [embed_one(client, t, sem) for t in texts]
    # return_exceptions keeps one failure from cancelling the batch
    return await asyncio.gather(*tasks, return_exceptions=True)

# results = asyncio.run(embed_all(client, documents))
# ok = [r for r in results if not isinstance(r, Exception)]
The async rule that catches everyone

One blocking call poisons the whole event loop. A single time.sleep(), requests.get() or synchronous database call inside an async def freezes every other coroutine, because they all share one thread. Use asyncio.sleep, httpx.AsyncClient, and async database drivers — or push the blocking call out with await asyncio.to_thread(fn, ...). Symptoms are baffling: throughput collapses under load with no error anywhere.

Habits worth carrying over from Java

Pin dependency versions and commit the lockfile. Fail CI on type errors and lint violations, not just tests. Keep a pyproject.toml as the single source of project configuration. Structure code as a package with an entry point rather than a pile of scripts. None of this is enforced by Python culture the way it is by Java tooling — which means the discipline you already have is a genuine advantage in a Python codebase.

Section 08 ProfessionalExercises

Do these — roughly two evenings
  1. Reproduce the mutable-default bug, then fix it. Enable ruff and confirm it flags the original.
  2. Rewrite a Java stream pipeline you have written recently as a Python comprehension. Compare readability honestly.
  3. Write a generator that streams a 1 GB file in chunks. Confirm with a memory profiler that resident memory stays flat.
  4. Write the @retry decorator from Section 03 yourself, without looking. Add jitter. Test it with a function that fails twice then succeeds.
  5. Define a Pydantic model for a tool your service could expose. Print its JSON Schema — that is literally what you send to a model in §5.1.
  6. Write an async script that embeds 500 texts with a concurrency limit of 10. Then remove the semaphore and observe the rate limiting.
  7. Set up a project with uv, add ruff and mypy, and make CI fail on a deliberate type error. This is the safety net you are used to.
