Section 01 BeginnerStart from zero

Assumed knowledge

Basic Python (Topic 2.1) and, for Section 06 onwards, familiarity with SQL. No mathematics beyond arithmetic is required.

Two libraries, two jobs. NumPy handles grids of numbers — fast. Pandas handles tables with named, mixed-type columns — conveniently. Almost every Python data or AI library is built on one or both, so learning them is not optional overhead; it is the vocabulary.

Why not just use lists?

A Python list of a million numbers is a million separate objects scattered across memory, each carrying a type tag and a reference count. Adding two such lists means a million interpreter loop iterations, each dispatching on type.

A NumPy array of a million numbers is one contiguous block of raw bytes, all the same type. Adding two of them is a single call into optimised C that uses the CPU's vector instructions.

PythonThe difference, measured
import numpy as np, time

n = 5_000_000
py_a, py_b = list(range(n)), list(range(n))
np_a, np_b = np.arange(n), np.arange(n)

t = time.perf_counter()
py_c = [x + y for x, y in zip(py_a, py_b)]
print(f"python list : {time.perf_counter() - t:.3f}s")

t = time.perf_counter()
np_c = np_a + np_b
print(f"numpy array : {time.perf_counter() - t:.3f}s")

# python list : 0.412s
# numpy array : 0.011s     ~40x, and the gap widens with more work per element

print(np_a.nbytes / 1e6, "MB")      # 40.0 MB -- exactly 8 bytes x 5M
# The list needs roughly 200 MB for the same numbers.
The words, in plain English
ndarray
NumPy's array. Fixed size, one single type throughout, laid out contiguously in memory.
dtype
The type of every element: float32, int64, bool. Choosing it is a real decision — float32 halves your memory versus float64.
Shape
A tuple giving the size along each axis. (1000, 768) is a thousand 768-dimensional vectors.
Axis
Which direction an operation runs. axis=0 collapses rows (down the columns); axis=1 collapses columns (across the rows).
Vectorisation
Expressing a whole-array operation instead of a loop. The core skill of this page.
Broadcasting
NumPy automatically stretching a smaller array to match a bigger one, without copying it.
DataFrame
Pandas' table: named columns, each with its own type, sharing a row index. Effectively an in-memory result set.
Series
A single column of a DataFrame. A one-dimensional labelled array.

Section 02 IntermediateWhat an ndarray actually is

An ndarray is a thin descriptor over a flat buffer. Understanding the descriptor explains several behaviours that otherwise look arbitrary.

data
Pointer to one flat block of bytes
dtype
How to interpret each element
shape
Logical dimensions
strides
Bytes to step to advance one along each axis

Strides are the interesting one. For a (3, 4) array of float64, strides are (32, 8): move 32 bytes to go down a row, 8 bytes to move along one. Now consider a transpose — NumPy just swaps the strides to (8, 32). No data moves at all. Transposing a gigabyte array is instantaneous.

PythonViews, copies, and the bug this causes
import numpy as np

a = np.arange(12).reshape(3, 4)
print(a.strides)          # (32, 8)
print(a.T.strides)        # (8, 32)  -- same buffer, swapped strides
print(a.T.base is a)      # True     -- a VIEW, not a copy

# Slicing returns a view. Writing to it mutates the original.
row = a[1]
row[0] = 999
print(a[1, 0])            # 999   -- surprising if you expect a copy

# Fancy indexing returns a COPY.
picked = a[[0, 2]]
picked[0, 0] = -1
print(a[0, 0])            # 0     -- original untouched

# The rule: basic slicing -> view; boolean or integer-array
# indexing -> copy. Use .copy() whenever you mean it.

# Contiguity matters for speed:
print(a.flags["C_CONTIGUOUS"])    # True
print(a.T.flags["C_CONTIGUOUS"])  # False -- some ops will copy internally
b = np.ascontiguousarray(a.T)     # force a contiguous copy if it matters

Section 03 IntermediateBroadcasting, derived

Broadcasting is what lets you write matrix / vector and have it mean something sensible. The rules are short, mechanical, and worth memorising because they explain most shape errors.

  1. Align the shapes from the right. Pad the shorter shape with 1s on the left. (1000, 768) and (768,) become (1000, 768) and (1, 768).
  2. Compare each axis. They are compatible if they are equal, or if one of them is 1.
  3. Stretch the 1s. An axis of size 1 is repeated to match. No memory is allocated — NumPy sets that axis's stride to 0 so the same element is read repeatedly.
  4. Otherwise, error. If any axis pair is neither equal nor contains a 1, the operation fails.
PythonBroadcasting in the operations you will actually write
import numpy as np

store = np.random.randn(100_000, 768)     # 100k embeddings

# Normalise every row. norms is (100000, 1); it broadcasts across
# all 768 columns. keepdims=True is what preserves that trailing 1.
norms = np.linalg.norm(store, axis=1, keepdims=True)   # (100000, 1)
store = store / norms                                  # (100000, 768)

# WITHOUT keepdims you get (100000,), which right-aligns against
# the 768 axis and raises: operands could not be broadcast
# together with shapes (100000,768) (100000,)

query = np.random.randn(768)
query /= np.linalg.norm(query)

scores = store @ query                    # (100000,768)@(768,) -> (100000,)
top5 = np.argpartition(-scores, 5)[:5]    # O(n), unlike a full argsort
top5 = top5[np.argsort(-scores[top5])]

# Pairwise distances between two sets, no loop:
A = np.random.randn(500, 64)
B = np.random.randn(300, 64)
# (500,1,64) - (1,300,64) -> (500,300,64), then reduce the last axis
d = np.linalg.norm(A[:, None, :] - B[None, :, :], axis=-1)   # (500, 300)

# That allocates 500*300*64 floats = 76 MB. For large sets use the
# expansion ||a-b||^2 = ||a||^2 + ||b||^2 - 2a.b instead:
d2 = (A**2).sum(1)[:, None] + (B**2).sum(1)[None, :] - 2 * A @ B.T
print(np.allclose(d, np.sqrt(np.maximum(d2, 0)), atol=1e-5))   # True
The debugging habit that saves hours

When a NumPy expression misbehaves, print every .shape in the chain before anything else. Broadcasting almost never errors when you have made a conceptual mistake — it does something reasonable that you did not intend, and returns an array of the wrong shape that flows onward silently. Adding assert x.shape == (n, d) at function boundaries is the Python equivalent of a type signature, and worth the two lines.

Section 05 IntermediatePandas as SQL you can hold

A DataFrame is a result set that lives in memory and can be transformed step by step. Your SQL transfers almost completely; the main new idea is the index, a labelled row identifier that operations align on automatically.

.loc, .iloc, and chained assignment

.loc selects by label and its slices are inclusive of the endpoint; .iloc selects by position and is exclusive, like Python slicing. Mixing them up is the most common Pandas error.

Worse is chained assignment: df[df.x > 5]["y"] = 0 may write to a temporary copy and silently do nothing. Always assign through a single .loc: df.loc[df.x > 5, "y"] = 0. Pandas 3 makes this an error by default; until then it is a warning that is easy to ignore and expensive to miss.

Section 06 AdvancedBuild an evaluation analysis pipeline

A realistic task you will do repeatedly: you have run an eval suite across several prompt versions and models, and you need to answer "which configuration should we ship?" — with cost and latency accounted for.

PythonFrom raw eval logs to a shipping decision
import pandas as pd, numpy as np

runs = pd.read_json("eval_runs.jsonl", lines=True)
# columns: case_id, model, prompt_version, passed, latency_ms,
#          input_tokens, output_tokens, answer, timestamp

# --- 1. always look before you compute --------------------------
print(runs.shape, runs.dtypes.to_dict())
print(runs.isna().sum())                  # where is data missing?
print(runs.describe(include="all").T)

# --- 2. derive the columns you actually care about ---------------
PRICE = {"opus": (15.0, 75.0), "sonnet": (3.0, 15.0)}   # $/M in, $/M out

def cost_row(r):
    inp, out = PRICE.get(r.model, (0.0, 0.0))
    return r.input_tokens / 1e6 * inp + r.output_tokens / 1e6 * out

runs["cost_usd"] = runs.apply(cost_row, axis=1)
runs["timestamp"] = pd.to_datetime(runs.timestamp)

# --- 3. group and summarise --------------------------------------
summary = (
    runs.groupby(["model", "prompt_version"])
        .agg(n           = ("passed", "size"),
             pass_rate   = ("passed", "mean"),
             p50_ms      = ("latency_ms", lambda s: s.quantile(0.50)),
             p95_ms      = ("latency_ms", lambda s: s.quantile(0.95)),
             cost_per_1k = ("cost_usd", lambda s: s.mean() * 1000))
        .reset_index()
)

# --- 4. a confidence interval, so you do not ship noise ----------
#     Wald interval: p +/- 1.96 * sqrt(p(1-p)/n)
p, n = summary.pass_rate, summary.n
summary["ci95"] = 1.96 * np.sqrt(p * (1 - p) / n)
summary["lower_bound"] = (p - summary.ci95).clip(0, 1)

# Rank by the PESSIMISTIC estimate, not the point estimate --
# this automatically penalises configurations tested on few cases.
summary = summary.sort_values("lower_bound", ascending=False)
print(summary.round(4).to_string(index=False))

# --- 5. which cases regressed between two versions? --------------
wide = (runs[runs.model == "sonnet"]
        .pivot_table(index="case_id", columns="prompt_version",
                     values="passed", aggfunc="first"))
regressed = wide[(wide["v3"] == False) & (wide["v2"] == True)]
print(f"{len(regressed)} cases regressed from v2 to v3")
print(regressed.index.tolist()[:10])

# --- 6. attach human labels held elsewhere ------------------------
labels = pd.read_csv("human_labels.csv")            # case_id, label
merged = runs.merge(labels, on="case_id", how="left", indicator=True)
print(merged._merge.value_counts())    # ALWAYS check the join worked
# left_only rows mean unlabelled cases -- a silent join failure is
# the most common source of wrong analysis.
The indicator=True habit

Join bugs are the leading cause of quietly wrong data analysis, and they never raise. A key type mismatch (int64 vs object), stray whitespace, or duplicate keys will silently drop or multiply rows. indicator=True adds a _merge column showing which side each row came from — check its value counts after every join, exactly as you would check rowsAffected after an UPDATE.

Section 07 ProfessionalPerformance and scale

Making Pandas fast, in order of impact
TechniqueGainWhen
Replace .apply / .iterrows with vectorised ops10–100×Always. iterrows is the slowest thing in Pandas
category dtype for repeated strings10× memoryLow-cardinality columns like model name or status
Downcast numerics2–4× memoryfloat32, int32 where range permits

usecols / dtype on readLargeDo not load columns you will drop
Chunked readingUnboundedchunksize= for files bigger than memory

A recommendation worth acting on. For a Java developer with strong SQL, DuckDB is often a better tool than Pandas for analysis: you write ordinary SQL directly against Parquet or CSV files, it is columnar and parallel, and it hands results back as a DataFrame when you want one. Learn enough Pandas to read other people's code — which is a lot of code — then use DuckDB for your own analysis and keep your existing skills.

Section 08 ProfessionalExercises

Do these — roughly two evenings
  1. Reproduce the list-vs-array timing. Then repeat with a more expensive per-element operation and note that the gap widens.
  2. Trigger the keepdims broadcasting error deliberately, read the message carefully, and fix it. That error message will now be instantly recognisable.
  3. Implement cosine similarity search over 100k random vectors using broadcasting, then again with argpartition for top-k. Time both against a full argsort.
  4. Verify that a.T is a view by mutating through it. Then verify that fancy indexing is a copy.
  5. Implement the pairwise-distance expansion ||a||² + ||b||² - 2a·b and confirm it matches the broadcast version. Compare peak memory for 5,000×5,000.
  6. Take any CSV you have, load it, and reduce its memory by 4× using category dtypes and downcasting. Check with df.memory_usage(deep=True).
  7. Build the eval summary pipeline on your own data. Include the confidence interval, and find one "improvement" that turns out to sit inside the noise.
  8. Do the same analysis in DuckDB with SQL. Decide which you would rather maintain.
