Step 01Why fine-tune at all

Atlas already has RAG for facts, so why train a model? Because fine-tuning teaches something RAG cannot: behaviour. The house tone, the concise support style, the company's terminology and formatting conventions — the how, not the what (Topic 3.5).

The division of labour

Keep the two mechanisms doing what each is good at. RAG injects knowledge — fresh, citable, updatable without retraining. Fine-tuning shapes behaviour — style, format, following the company's answer patterns. Trying to fine-tune facts into the weights is expensive, goes stale, and hallucinates; trying to prompt a generic model into a consistent house voice is unreliable. Atlas does both, each for its strength (Topics 3.5, 4.1). This chapter handles the behaviour half.

Step 02LoRA: the maths that makes it fit

A full fine-tune updates every weight in the model — billions of numbers, needing enormous VRAM (Topic 6.5). LoRA (Low-Rank Adaptation) freezes the original weights and learns a tiny low-rank update instead, cutting trainable parameters by ~99% (Topic 3.5).

LoRA — a low-rank update beside a frozen weight h = W₀x + ΔW x = W₀x + B A x W₀ ∈ ℝd×d (frozen)  ·  B ∈ ℝd×r, A ∈ ℝr×d,   r ≪ d The big update ΔW is factored into two skinny matrices B and A of rank r (say 16). Instead of training d×d numbers you train 2·d·r — a tiny fraction. The original W₀ never moves, so you keep the base model's knowledge and only add a small learned adjustment. This is why a 7B model fine-tunes on one consumer GPU.
QLoRA — smaller still

QLoRA goes further: it loads the frozen base model in 4-bit (Topic 18.3) while training the LoRA adapters in 16-bit on top. The giant frozen weights take a quarter of the memory; the tiny trainable adapters keep full precision where it matters. The combination is what lets you fine-tune even a large Llama on a single modest GPU — the technique that democratised fine-tuning. It leans directly on the quantisation of Topic 18.3 and the mixed-precision maths of Topic 2.6.

Step 03The training loop

PythonQLoRA fine-tune of Llama with PEFT + TRL
from transformers import AutoModelForCausalLM, BitsAndBytesConfig
from peft import LoraConfig
from trl import SFTTrainer

bnb = BitsAndBytesConfig(load_in_4bit=True,           # QLoRA: 4-bit base (Ch. 18.3)
                         bnb_4bit_quant_type="nf4",
                         bnb_4bit_compute_dtype="bfloat16")  # compute in bf16 (Ch. 2.6)
base = AutoModelForCausalLM.from_pretrained(
    "meta-llama/Llama-3.1-8B", quantization_config=bnb, device_map="auto")

lora = LoraConfig(r=16, lora_alpha=32, lora_dropout=0.05,
                  target_modules=["q_proj", "v_proj"],  # adapt attention
                  task_type="CAUSAL_LM")

trainer = SFTTrainer(model=base, peft_config=lora,
                     train_dataset=train_set,           # from Ch. 20.2
                     args=TrainingArguments(
                         per_device_train_batch_size=4,
                         gradient_accumulation_steps=8,  # big effective batch (Ch. 9.6)
                         bf16=True, learning_rate=2e-4, num_train_epochs=3))
trainer.train()
trainer.model.save_pretrained("atlas-lora")            # just the adapters -- tiny

Step 04What the model is optimising

Under the hood, fine-tuning is the same next-token prediction the model was pre-trained on (Topic 1.3), driven by cross-entropy loss — the model is rewarded for putting probability on the actual next token of each training answer.

Cross-entropy — the language-model loss L = − 1N ∑t=1N log P(xt | x<t) For each position t, take the probability the model assigned to the correct next token xt, take its log, average, negate. Perfect confidence in the right token → loss 0; spreading probability onto wrong tokens → higher loss. Gradient descent (Topic 1.4) nudges the LoRA weights B, A to reduce it, backprop computing the gradients (Topic 2.4). This is the entire learning signal.
Fine-tuning is easy to get subtly wrong

Three traps to respect. Overfitting: too many epochs on a small set and the model parrots the training data and loses generality — watch a held-out loss, stop when it turns up. Catastrophic forgetting: aggressive fine-tuning can erode the base model's broad ability; LoRA mitigates this by leaving W₀ frozen. Bad data in, bad model out: the model faithfully learns whatever is in the training set, so the audit from chapter 20.2 matters more than any hyperparameter. Measure the result on the real eval set (Ch. 20.9), never on the training data.
