Section 01 BeginnerStart from zero

Assumed knowledge

Sections 01–02 assume no calculus at all. If you have never differentiated anything, start here and you will be fine. Section 04 onwards assumes you have followed Sections 02–03.

Every model that "learns" is doing the same thing: it has millions of adjustable numbers, a way of measuring how wrong it currently is, and a procedure for nudging each number in the direction that makes it less wrong. Calculus is the procedure for working out which direction that is.

The hill-descending picture

Imagine standing on a foggy hillside, trying to reach the valley. You cannot see the valley — the fog is too thick. But you can feel the slope under your feet. So you take a small step downhill, feel the slope again, take another step, and repeat. Eventually you reach the bottom.

That is gradient descent, complete. The hill is the loss — how wrong the model is. Your position is the current setting of every parameter. The slope you feel is the gradient. The size of your step is the learning rate.

The words, in plain English
Function
A rule that turns an input into an output. f(x) = x2 turns 3 into 9.
Derivative
How fast the output changes when you nudge the input. If nudging x up by a hair makes f(x) go up by three hairs, the derivative is 3. It is a rate, and it is also the slope of the graph at that point.
Gradient
The derivative when there are many inputs instead of one — a list containing one derivative per input. It points in the direction of steepest increase, which is why you move in the opposite direction.
Loss function
A single number measuring how wrong the model currently is. Lower is better. Training means minimising it.
Learning rate
How big a step to take. Too big and you overshoot the valley; too small and you never arrive.
Backpropagation
An efficient method for computing the gradient of every parameter in a deep network. It is the chain rule, applied backwards. That is all it is.
Convergence
Reaching the point where further steps stop helping. Training is finished.
Why you need this even though you will never train a model

You are not going to train a foundation model. But you will read training scripts, choose a learning rate for a LoRA fine-tune, debug a loss that will not go down, and interpret a training curve. Each of those requires the mental picture above. More importantly: the reason a model can be trained at all is that every operation in it is differentiable, and that constraint explains a surprising number of architectural choices — including why attention uses a soft softmax rather than a hard lookup.

How fast is f(x) = x2 changing at x = 3? Measure it: move a small distance h and see how much the output moved.

The answer is converging on 6. That limiting value is the derivative, and the definition simply says "do this forever":

The derivative, by definition f′(x)  =  limh→0 f(x+h) − f(x)h Rise over run, with the run shrunk to nothing. Everything else in calculus is a shortcut for evaluating this limit without doing the arithmetic each time.
Deriving the power rule for x2
  1. f′(x) = limh→0 [(x+h)2 − x2] / h Substitute f(x) = x2 into the definition.
  2. = limh→0 [x2 + 2xh + h2 − x2] / h Expand the square.
  3. = limh→0 [2xh + h2] / h = limh→0 (2x + h) The x2 terms cancel; divide through by h.
  4. = 2x. At x=3 this is 6.  ■ Send h to zero. Matches the table exactly.

Why sigmoid fell out of favour

Its derivative peaks at 0.25 and approaches zero for inputs away from the origin. Stack ten sigmoid layers and gradients get multiplied by numbers under 0.25 ten times over — a factor of about one in a million. The early layers receive essentially no signal and stop learning. This is the vanishing gradient problem, and it is why deep networks did not work before ReLU (whose derivative is exactly 1 in the active region) and residual connections (which give gradients a path that skips the multiplication entirely).

Section 03 IntermediateThe chain rule is the whole of backpropagation

A neural network is functions inside functions inside functions. To adjust a weight in layer 1, you need to know how it affects the loss at the far end — through every intervening layer. The chain rule is the tool for exactly that.

The chain rule If y = f(u) and u = g(x), then   dydx = dydu · dudx Rates multiply. If a car is twice as fast as a bicycle, and the bicycle is three times as fast as walking, the car is six times as fast as walking. That is the entire intuition, and it extends to any depth by repeating the multiplication.

Backpropagation, derived on a real example

Take the smallest network that is still interesting: one input, two layers, a sigmoid, and a squared-error loss. Work out how the loss responds to w1, the weight furthest from the output.

Forward pass, then backward pass
  1. z1 = w1x + b1   a1 = σ(z1)   z2 = w2a1 + b2   L = ½(z2 − y)2 The forward pass. Each line depends only on the one above — a chain.
  2. ∂L/∂z2 = (z2 − y) Start at the end. The ½ exists precisely so this comes out clean.
  3. ∂L/∂a1 = ∂L/∂z2 · w2 One link back. Since z2 = w2a1+b2, the local derivative is w2.
  4. ∂L/∂z1 = ∂L/∂a1 · σ(z1)(1−σ(z1)) Through the sigmoid, using its derivative from the table above.
  5. ∂L/∂w1 = ∂L/∂z1 · x Final link. Since z1 = w1x+b1, the local derivative is x.  ■
The insight that makes it efficient

Look at lines 2–5. Each reuses the result of the previous one and multiplies by a purely local derivative. Nothing is recomputed. That is why backpropagation costs roughly the same as one forward pass, regardless of how many parameters there are.

The naive alternative — nudge each parameter and re-run the network to see what changed — would need one forward pass per parameter. For a 7-billion-parameter model that is 7 billion forward passes per training step. Backpropagation is what makes deep learning computationally possible, and it is nothing more than caching intermediate results while applying the chain rule right to left.

Section 04 AdvancedBuild an autograd engine from scratch

PyTorch's loss.backward() feels like magic until you write one. It is not magic: every operation records how to propagate a gradient through itself, and the framework walks the recorded graph backwards. Sixty lines is enough for a working version.

PythonA miniature automatic differentiation engine
import math

class Value:
    """A scalar that remembers how it was computed."""

    def __init__(self, data, _children=(), _op=""):
        self.data = float(data)
        self.grad = 0.0
        self._backward = lambda: None      # how to push grad to parents
        self._prev = set(_children)
        self._op = _op

    def __repr__(self):
        return f"Value({self.data:.4f}, grad={self.grad:.4f})"

    def __add__(self, other):
        other = other if isinstance(other, Value) else Value(other)
        out = Value(self.data + other.data, (self, other), "+")
        def _backward():
            # d(a+b)/da = 1, so gradient passes straight through.
            # += not = : a value used twice accumulates both paths.
            self.grad  += out.grad
            other.grad += out.grad
        out._backward = _backward
        return out

    def __mul__(self, other):
        other = other if isinstance(other, Value) else Value(other)
        out = Value(self.data * other.data, (self, other), "*")
        def _backward():
            # d(a*b)/da = b -- the OTHER operand is the local derivative
            self.grad  += other.data * out.grad
            other.grad += self.data  * out.grad
        out._backward = _backward
        return out

    def __pow__(self, k):
        assert isinstance(k, (int, float))
        out = Value(self.data ** k, (self,), f"**{k}")
        def _backward():
            self.grad += k * (self.data ** (k - 1)) * out.grad   # power rule
        out._backward = _backward
        return out

    def relu(self):
        out = Value(max(0.0, self.data), (self,), "relu")
        def _backward():
            self.grad += (out.data > 0) * out.grad               # 1 or 0
        out._backward = _backward
        return out

    def sigmoid(self):
        s = 1 / (1 + math.exp(-self.data))
        out = Value(s, (self,), "sigmoid")
        def _backward():
            self.grad += s * (1 - s) * out.grad                  # sigma'(x)
        out._backward = _backward
        return out

    # conveniences so ordinary arithmetic works
    def __neg__(self):        return self * -1
    def __sub__(self, o):     return self + (-o)
    def __radd__(self, o):    return self + o
    def __rmul__(self, o):    return self * o
    def __truediv__(self, o): return self * (o ** -1 if isinstance(o, (int, float))
                                             else o.__pow__(-1))

    def backward(self):
        """Topologically sort the graph, then apply the chain rule
        in reverse. A node is only processed once all its consumers
        have contributed their gradient."""
        order, seen = [], set()
        def build(v):
            if v not in seen:
                seen.add(v)
                for child in v._prev:
                    build(child)
                order.append(v)
        build(self)

        self.grad = 1.0                    # dL/dL = 1: seed the chain
        for node in reversed(order):
            node._backward()

L.backward()

# Verify numerically: nudge w1 and re-measure the loss.
h = 1e-6
def loss_with(w):
    a = 1 / (1 + math.exp(-(w * 2.0 + 0.1)))
    return 0.5 * (1.5 * a - 0.3 - 1.0) ** 2
numeric = (loss_with(-0.5 + h) - loss_with(-0.5 - h)) / (2 * h)
print(f"numeric = {numeric:.6f}")          # matches to ~6 decimal places
The two subtleties in that code

Why += and not =. If a value feeds two branches, gradient arrives from both, and the total effect is the sum. Using = would silently discard one path — a bug that produces a network which trains, badly, for reasons that are very hard to find.

Why topological order. A node's gradient is only complete once every consumer has contributed. Processing in reverse topological order guarantees that. This is the same dependency-ordering problem as a build system resolving a task graph.

Section 05 AdvancedFrom SGD to Adam, one problem at a time

Once you have gradients, you need a rule for using them. Each optimiser exists because of a specific failure of the one before it — which makes them much easier to remember as a sequence than as a list.

Plain gradient descent θt+1  =  θt − η · ∇L(θt) Step downhill by the learning rate η times the slope. Simple, and inadequate for three specific reasons addressed below.
  1. Problem: computing the gradient over the whole dataset is too slow.
    Fix — Stochastic / mini-batch GD. Estimate the gradient from a small batch. The estimate is noisy, but you get hundreds of steps in the time one exact step would take, and the noise turns out to help escape shallow minima.
  2. Problem: in a narrow valley the path oscillates across the walls instead of running along the floor.
    Fix — Momentum. Accumulate a velocity, vt = βvt−1 + ∇L, and step along v. Oscillating components cancel between steps; consistent components reinforce. It is a ball rolling downhill rather than a hiker re-deciding at every footfall.
  3. Problem: one learning rate cannot suit all parameters — rare features need large steps, common ones small.
    Fix — RMSProp. Track a running average of squared gradients and divide the step by its square root. Parameters with historically large gradients get smaller steps automatically.
  4. Problem: you want both of those at once.
    Fix — Adam. Keep momentum and per-parameter scaling. This is the default for essentially every transformer.
Adam, in full mt = β1mt−1 + (1−β1)gt  first moment — momentum vt = β2vt−1 + (1−β2)gt2  second moment — scale m̂t = mt/(1−β1t)   v̂t = vt/(1−β2t)  bias correction θt = θt−1 − η · m̂t / (√v̂t + ε) Why bias correction exists: m and v start at zero, so early estimates are biased toward zero and the first steps would be far too small. Dividing by (1−βt) — which is near 0 early and near 1 later — exactly cancels that bias. Defaults β1=0.9, β2=0.999, ε=10−8 are near-universal and rarely worth changing.
PythonEvery optimiser, implemented and compared
import numpy as np

class SGD:
    def __init__(self, lr=0.01, momentum=0.0):
        self.lr, self.momentum, self.v = lr, momentum, None
    def step(self, params, grads):
        if self.v is None:
            self.v = np.zeros_like(params)
        self.v = self.momentum * self.v + grads
        return params - self.lr * self.v

class Adam:
    def __init__(self, lr=1e-3, b1=0.9, b2=0.999, eps=1e-8, weight_decay=0.0):
        self.lr, self.b1, self.b2, self.eps = lr, b1, b2, eps
        self.wd = weight_decay
        self.m = self.v = None
        self.t = 0
    def step(self, params, grads):
        if self.m is None:
            self.m = np.zeros_like(params)
            self.v = np.zeros_like(params)
        self.t += 1
        self.m = self.b1 * self.m + (1 - self.b1) * grads
        self.v = self.b2 * self.v + (1 - self.b2) * grads ** 2
        m_hat = self.m / (1 - self.b1 ** self.t)
        v_hat = self.v / (1 - self.b2 ** self.t)
        # AdamW: decay weights directly, NOT via the gradient.
        # Adding wd*params to grads instead would let the adaptive
        # scaling distort the regularisation -- that was Adam's bug.
        params = params - self.lr * self.wd * params
        return params - self.lr * m_hat / (np.sqrt(v_hat) + self.eps)

# A deliberately ill-conditioned bowl: 100x steeper in one direction.
def loss(p):  return 0.5 * (100 * p[0] ** 2 + p[1] ** 2)
def grad(p):  return np.array([100 * p[0], p[1]])

for name, opt in [("SGD          ", SGD(lr=0.01)),
                  ("SGD+momentum ", SGD(lr=0.01, momentum=0.9)),
                  ("Adam         ", Adam(lr=0.1))]:
    p = np.array([1.0, 1.0])
    for _ in range(100):
        p = opt.step(p, grad(p))
    print(f"{name} final loss {loss(p):.3e}")

# SGD           final loss 1.71e-01   crawls along the flat direction
# SGD+momentum  final loss 6.02e-06   momentum accelerates it
# Adam          final loss 1.24e-11   per-parameter scaling wins outright

You will spend far more time interpreting curves than deriving formulas. This table is the diagnostic manual.

Learning-rate schedules

A fixed learning rate is rarely right for the whole run. The standard recipe for transformers is linear warmup then cosine decay: start near zero and ramp up over the first few hundred steps, then decay smoothly toward zero.

Warmup exists because Adam's second-moment estimate v is unreliable in the first few steps — it has seen almost no data — and a full-size step based on a bad estimate can throw the model somewhere it never recovers from. Decay exists because large steps are useful for finding the right basin and harmful for settling into it.

Local minima are not your problem

Introductory material worries a great deal about getting stuck in local minima. In high-dimensional spaces this turns out to be largely a non-issue: for a point to be a local minimum, the loss must curve upward in every one of millions of directions simultaneously, which is vanishingly unlikely. Almost every stationary point is a saddle — up in some directions, down in others — and momentum carries you through those. The real problems are the practical ones in the table above: bad learning rates, exploding gradients and overfitting.

Section 07 ProfessionalExercises

Do these — roughly one evening
  1. Reproduce the shrinking-h table for f(x) = x3 at x=2. Confirm it converges to 12, then confirm the power rule predicts 3x2 = 12.
  2. Type in the Value class. Add tanh and exp methods with their correct backward functions, and gradient-check both numerically.
  3. Deliberately change one += to = in a backward function. Build an expression that uses a value twice and watch the gradient come out wrong. This is the bug you would otherwise ship one day.
  4. Use your Value class to fit a two-layer network to XOR. It needs a hidden layer — XOR is not linearly separable, and discovering that empirically is instructive.
  5. Run the optimiser comparison. Then set Adam's b2=0.9 and watch it behave more like RMSProp. Understanding the two moments separately is worth the five minutes.
  6. Implement linear warmup plus cosine decay and plot the learning rate against step. Overlay a run without warmup and note the early instability.
