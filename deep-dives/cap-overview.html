Step 01What we are building

Atlas is a realistic, buildable AI system: an internal knowledge assistant. A user asks a question in natural language; Atlas retrieves the relevant passages from the company's document corpus, reasons over them with a language model that has been fine-tuned on the company's own material, optionally calls tools (search a ticket system, look up a definition), and returns a grounded, cited answer — served over an API, evaluated, cost-optimised, and deployed.

It is deliberately chosen to exercise both of the paths that matter: RAG (retrieval over documents) and LLM training (fine-tuning an open Llama model and running it locally in llama.cpp). Every chapter builds one part, shows the code and the maths, and names the handbook topics it draws on.

Read the diagram as two loops. The offline loop (chapter 20.2) prepares data once: it cleans the corpus, chunks it for retrieval, and carves out an instruction set for fine-tuning and an evaluation set for measurement. The online loop serves each request: cache → agent → (retrieve ⊕ reason with the model) → answer. Everything else — evaluation, efficiency, deployment, safety — wraps around those two loops.

Step 04The decisions behind it

Before any code, the design questions from the handbook's system-design material (Topic 17.4) — answered for Atlas, because every one shapes what we build.

Design decisions
QuestionAtlas's answer & why
RAG or fine-tune?Both — RAG for facts (fresh, cited), fine-tuning for the house style and domain terms (Topic 4.1)
Which model?An open Llama — so we can fine-tune it and run it privately (Topic 9.2)
Cloud or local?Local inference — the corpus is internal; privacy matters (Topics 6.4, 19.4)
Agent or pipeline?A light agent — it needs to choose between retrieval and tools (Topic 5.2)
How do we know it works?An eval set from day one — not vibes (Topic 19.1)

Step 05How the chapters run

The build order

We build bottom-up, the way you actually would. Data first (20.2) — nothing works without it. Then the retrieval half (20.3 embeddings, 20.4 the RAG core), because retrieval quality dominates answer quality. Then the model half (20.5 fine-tuning Llama, 20.6 running it in llama.cpp). Then we assemble the application (20.7 the agent, 20.8 the API). Finally we make it trustworthy and cheap (20.9 evaluation, 20.10 efficiency, 20.11 deployment & safety), and 20.12 indexes every handbook topic against the code that used it. Each chapter stands alone but assumes the ones before it. Start the build.
