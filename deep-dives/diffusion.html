12.5

Diffusion Models

How today's image generators actually work. This page explains the diffusion idea — destroy an image with noise step by step, then train a network to reverse it — why that turns out to be a stable, powerful way to generate, how text prompts steer it, why it runs in a compressed latent space, and the trade-offs against GANs.

Section 01 BeginnerStart from zero

Assumed knowledge

Neural network training (Topic 2.4), autoencoders and latent spaces (Topic 12.3), and CLIP-style text-image embeddings (Topic 6.2).

Stable Diffusion, DALL-E and Midjourney all run on diffusion models — and the core idea is wonderfully counterintuitive. To learn to create images, you first learn to destroy them.

The diffusion idea in one paragraph

Take a clear image and add a little random noise. Add a little more. Keep going until, after many steps, it is pure static — all structure gone. This "forward process" is easy and requires no learning. Now train a network to do one step of the reverse: given a slightly noisy image, predict the noise that was added, so you can subtract it and get a slightly cleaner image. Once the network can reliably remove a little noise, you can generate from scratch: start with pure random noise and run the network many times, each step removing a bit of noise, until a coherent image emerges from the static. Generation is denoising, run in reverse from nothing.

The words, in plain English
Forward process
Gradually adding noise to an image until it is pure static. No learning needed.
Reverse process
The learned part: removing noise step by step to recover (or create) an image.
Denoiser
The network trained to predict and remove the noise at each step.
Sampling steps
How many denoising steps to run. More = higher quality, slower.
Conditioning
Steering generation with a text prompt (or another input).
Latent diffusion
Running the whole process in a compressed space (Topic 12.3) to save compute.

Section 02 IntermediateThe two processes

PythonForward (easy) and reverse (learned)
import torch

# --- FORWARD: add noise. Trivial, no learning. -------------------
def add_noise(x0, t, betas):
    # A closed form lets you jump straight to any noise level t.
    alpha_bar = torch.cumprod(1 - betas, 0)[t]
    noise = torch.randn_like(x0)
    xt = alpha_bar.sqrt() * x0 + (1 - alpha_bar).sqrt() * noise
    return xt, noise                    # the noisy image AND the noise added

# --- TRAINING: teach the network to PREDICT the added noise ------
# For a random image and a random noise level, add noise, then ask
# the network to say what noise was added. That's the whole target.
def training_step(model, x0, betas):
    t = torch.randint(0, len(betas), (x0.size(0),))
    xt, true_noise = add_noise(x0, t, betas)
    predicted_noise = model(xt, t)       # the denoiser (a U-Net)
    return mse(predicted_noise, true_noise)   # simple, stable loss!

# --- GENERATION: start from pure noise, denoise step by step -----
def generate(model, betas, steps):
    x = torch.randn(1, 3, 64, 64)        # pure static
    for t in reversed(range(steps)):
        predicted_noise = model(x, t)
        x = remove_one_step_of_noise(x, predicted_noise, t, betas)
    return x                             # a coherent image emerges
Why diffusion is more stable than GANs

Look at the training loss: it is a plain mean-squared error between predicted and actual noise (Topic 2.4). That is a single, fixed, well-behaved objective — unlike the adversarial moving target that makes GANs so temperamental (Topic 12.4). There is no second network to balance, no mode collapse, no delicate equilibrium. The task ("predict the noise") is easy to state and stable to optimise, yet composing thousands of these tiny denoising steps produces astonishing images. This stability, plus full coverage of the data's variety, is exactly why diffusion overtook GANs for high-quality generation.

Section 03 AdvancedSteering it with text

Denoising from random noise gives you a random image. To generate "an astronaut riding a horse," you need to condition the denoiser on the prompt.

The prompt is turned into an embedding by a text encoder (a CLIP-style model, Topic 6.2), and that embedding is fed into the denoiser at every step via cross-attention (Topic 1.3). Now, instead of removing noise toward any plausible image, the network removes it toward an image that matches the text. Classifier-free guidance strengthens this: run the denoiser both with and without the prompt at each step and push harder in the prompt's direction, trading a little diversity for much closer adherence to the text. The prompt-following you experience in an image generator is this guidance mechanism at work.

The knobs you actually turn in an image generator
KnobEffect
PromptWhat to generate — the conditioning
StepsMore = higher quality, slower
Guidance scaleHow strictly to follow the prompt vs stay diverse
SeedThe starting noise; same seed + prompt = same image
Negative promptWhat to steer away from
ControlNet / img2imgCondition on a pose, sketch or existing image, not just text

Section 04 AdvancedLatent diffusion: making it affordable

Running diffusion directly on high-resolution pixels is enormously expensive — many denoising steps, each over millions of pixels. The breakthrough that made diffusion practical (and gave us Stable Diffusion) was to run it somewhere cheaper.

The autoencoder connection

Latent diffusion uses an autoencoder (Topic 12.3) to compress images into a small latent space — say 64×64 instead of 512×512 — runs the entire costly diffusion process in that compact space, and then decodes the final latent back to a full-resolution image. Because the latent is ~48× smaller, the whole process is dramatically cheaper, which is what let image generation run on consumer GPUs and become widely available. It is a perfect example of composing foundational pieces: an autoencoder for compression, diffusion for generation, and a text encoder for control, assembled into one system. Understanding each part (Topics 12.3, 6.2, and this page) demystifies the whole.

Section 05 ProfessionalTrade-offs and where it is going

Diffusion vs GANs, recapped
DiffusionGAN (Topic 12.4)
Training stabilityStable (fixed loss)Temperamental
Quality & diversityState-of-the-artGood; prone to mode collapse
ControlRich (prompts, ControlNet)Harder
SpeedSlow — many stepsFast — one pass

The active frontier is speed. Diffusion's one weakness is that it needs many sampling steps. A lot of recent work — distillation, consistency models, and few-step samplers — has driven the step count down from dozens toward a handful, closing the gap with GANs while keeping diffusion's quality and control. The same forward-then-reverse-noise idea is also generating video and audio now. For an application builder, you will consume these models through APIs and tools rather than train them, but knowing the mechanism explains the knobs (Section 03), the costs, and why quality and speed trade off the way they do.

Section 06 ProfessionalExercises

Do these — roughly a weekend
  1. Implement the forward noising process and visualise an image degrading to static over steps. Note it needs no learning.
  2. Train a tiny diffusion model on MNIST to predict noise, then generate digits from pure noise. Watch them emerge.
  3. Using a Stable Diffusion pipeline, generate the same prompt at 5, 20 and 50 steps. Compare quality and time.
  4. Fix the seed and vary the guidance scale from low to high. Observe prompt adherence vs diversity (Section 03).
  5. Use a negative prompt and img2img/ControlNet to condition on a sketch. See control beyond text.
  6. Explain to a friend, in three sentences, why "learning to destroy images teaches you to create them."
