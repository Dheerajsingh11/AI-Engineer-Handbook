Toolchain, Skills Map & Schedule

One page for the operational questions: every tool you need and why, which project builds which skill and which interview round tests it, how the five projects compose into a single system, what the whole thing costs, and the twelve-week schedule that ends with offers rather than a finished portfolio.

Five projects, one system

Each project is independently shippable, and each is also a layer of the same platform. Built in order, the gateway meters the RAG system, the RAG system becomes a tool for the agent, the eval suite gates all of them, and the fine-tuned model registers as a second provider behind the gateway. That composition is worth far more in an interview than five disconnected repositories — it is the difference between five tutorials and one system.

Two consequences worth stating in an interview. First, because every model call goes through the gateway, every project is costed automatically — you can answer “what does an agent task cost?” with a query rather than an estimate. Second, because the fine-tuned model registers behind the same Provider interface as the frontier API, the migration question in Project 4 becomes a configuration change plus an eval run, which is exactly the answer a design round is looking for.

Three deliberate omissions

No dedicated vector database. Pinecone, Weaviate and Qdrant are all fine, but pgvector keeps vectors next to the metadata you filter on, which is what makes pre-filtered access control simple. Know the trade-off; choose the simpler thing.

No framework in Projects 2 and 3 at first. LangChain and LlamaIndex are worth knowing and you will port to them — afterwards. Building the pipeline by hand once is what lets you answer questions about it.

No Kubernetes. It adds weeks and teaches nothing this loop tests. Docker Compose is enough.

Realistic budget for all five, over twelve weeks

Infrastructure$0Everything else runs locally in Docker.
Total$85–170Set a hard budget in the gateway on day one — then it enforces itself.
The runaway to guard against

The single most likely way to overspend is an agent loop without a turn cap running against a tool that keeps failing: each turn resends the whole growing history, so cost per turn climbs while nothing progresses. Put the cap in on day one of Project 3, and give your own gateway a hard monthly ceiling that returns a 402. Having done this is also a genuine cost-control story for the interview.

Step 07Repository conventions

An interviewer spends about four minutes in your repository before the call. These conventions are what they find.

MarkdownREADME.md — the structure that reads well in four minutes
# <Project>

One sentence on what it does and why it exists.

## Results
| metric              | baseline | current | how measured                |
|---------------------|----------|---------|-----------------------------|
| recall@10           | 0.61     | 0.83    | 150-question labelled set   |
| faithfulness        | 0.74     | 0.94    | calibrated judge, kappa 0.71|
| p95 latency         | 3.2s     | 1.4s    | 500 requests, concurrency 8 |
| cost / 1k requests  | $4.10    | $1.35   | gateway ledger              |

<-- This table goes ABOVE the architecture section. It is the only part
    some readers will look at, and it is what makes the rest credible. -->

## Architecture
One diagram, one paragraph.

## What did not work
Link to FINDINGS.md. Do not bury this.

## Run it
Three commands, maximum.
MarkdownFINDINGS.md — the highest-signal file in the portfolio
# Findings

## HyDE query expansion -- partially rejected
Tried: generate a hypothetical answer, embed that, search with it.
Result: +4 pts recall on ambiguous questions, -9 pts on precise ones
        (identifiers, error strings).
Decision: gated on query length and absence of an identifier pattern.

## Semantic cache threshold
Tried: 0.99 down to 0.85, hand-grading 50 hits at each level.
Result: below 0.95 the false-hit rate exceeded 6%, and a false hit means
        confidently answering a question nobody asked.
Decision: 0.95, with hits logged for audit.

## Prompt cache went to zero for two days
Cause: a request ID interpolated into the system prompt.
Detection: cache_read_input_tokens flat at 0 in the ledger.
Fix: moved the ID after the cache breakpoint. Cost impact: ~40% of spend
     that week.

Three rules that decide whether this works
  1. Measure before you optimise, every time. A naive baseline you can quote a number for is worth more in an interview than a sophisticated version you cannot.
  2. Write down what failed. FINDINGS.md is the file that proves you did the real thing, because tutorials never have one.
  3. Apply at week six. Loops take four to eight weeks. Projects 3, 4 and 5 will finish while you are interviewing, and “I am building that layer right now” is a strong answer.
