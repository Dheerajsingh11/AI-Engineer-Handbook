18.2

Synthetic Data Generation

Manufacturing the data you could not collect. This page covers synthetic data — using LLMs, simulation and statistical models to generate training and evaluation examples — why it became central to modern AI, where it genuinely helps, and the failure mode (model collapse) that punishes using it carelessly.

Section 01 BeginnerStart from zero

Assumed knowledge

Data engineering (Topic 18.1) and a working sense of LLMs (Topic 1.3). Synthetic data is a way to create the datasets the previous page taught you to manage.

Sometimes you cannot get the data you need. It is too rare (fraud, defects, edge cases), too sensitive (medical records, personal data), too expensive to label, or it simply does not exist yet. Synthetic data is artificially generated data made to stand in for real data — produced by a model, a simulator or a statistical process rather than collected from the world.

Why this went from niche to mainstream

Two things changed. First, LLMs became good enough to write convincing, varied, on-topic examples on demand — so generating a few thousand training or test cases costs a prompt, not a labelling budget. Second, the frontier labs ran low on high-quality human text and turned to synthetic and model-distilled data to keep improving. The result: synthetic data is now a standard tool for bootstrapping datasets, covering rare cases, and building evaluation sets — not a curiosity. But it comes with a sharp caveat this page builds towards (Section 05).

The words, in plain English
Synthetic data
Data generated artificially rather than collected from reality.
Augmentation
Making more training data by perturbing existing real examples.
Distillation data
Outputs from a strong "teacher" model used to train a smaller one (Topic 18.3).
Simulation
A programmed environment that produces realistic data (e.g. a driving simulator).
Model collapse
The decay that happens when models train on their own generated output, repeatedly.

PythonGenerating labelled examples with an LLM
# Bootstrapping a classification dataset when you have almost no data.
# The craft is in the prompt: demand variety, realism, and the label.
prompt = """Generate 5 realistic customer support messages that express
FRUSTRATION about late delivery. Vary the tone, length, product, and
phrasing. Return JSONL: {"text": ..., "label": "frustrated"}.
Avoid repeating sentence structures."""

rows = []
for _ in range(200):                      # many small, varied batches
    rows += parse_jsonl(llm(prompt, temperature=0.9))   # high temp = diversity

# CRUCIAL: audit a real sample by hand before trusting any of it.
# Deduplicate -- LLMs collapse toward a few templates (Section 04).
rows = dedupe(rows)

Section 03 IntermediateWhere it genuinely helps

Synthetic data is not a general replacement for real data. It shines in specific, identifiable situations.

The high-value use cases
SituationWhy synthetic helps
Cold startBootstrap a first dataset before you have real users
Rare eventsManufacture the fraud/defect cases reality gives you too few of
Privacy wallsGenerate "statistically real" data with no actual person in it
Evaluation setsAuthor targeted, adversarial test cases fast (Topic 19.1)
Fine-tuning & distillationCreate instruction/response pairs to teach a smaller model (Topics 3.5, 18.3)
Coverage gapsFill in demographics, languages or scenarios your real data misses
The pattern that works best

The reliable recipe is synthetic to bootstrap, real to finish. Generate synthetic data to get moving — a first model, a first eval set, coverage of a rare case — then replace or supplement it with real data as it arrives, always keeping a real held-out test set so your measured performance reflects reality, not your generator. Synthetic training data with a synthetic test set can look flawless and mean nothing.

Section 04 AdvancedQuality, diversity & model collapse

Two problems decide whether synthetic data helps or quietly poisons your model: it can lack diversity, and training on it recursively can cause collapse.

Model collapse

Train a model on data generated by models, whose data was generated by models, and quality degrades generation over generation: the distribution narrows, the tails (rare but real cases) vanish, and outputs converge toward a bland average. This is model collapse, and it is a genuine, measured phenomenon. The mechanism is simple — each generation samples from the last and loses a little of the true variance — and the defence is equally clear: keep real data in the mix, never train purely on your own outputs, and monitor diversity, not just accuracy.

Diversity is the metric that matters

The characteristic weakness of LLM-generated data is mode collapse in miniature: ask for 500 examples and you get five templates with the words swapped. A model trained on that learns the templates, not the task. So the quality bar for synthetic data is not "does each example look real?" but "is the set as varied as reality?" Measure it: cluster the examples and check the spread, compute embedding diversity (Topic 4.2), deduplicate aggressively, raise temperature and vary the prompt, and seed generation with different real examples. A smaller, more diverse synthetic set beats a large, repetitive one every time.

Section 05 ProfessionalUsing it responsibly

The professional checklist
ConcernPractice
RealismHuman-audit a sample; compare distributions to real data
DiversityMeasure spread; dedupe; vary prompts and seeds (Section 04)
BiasThe generator's biases become your dataset's biases (Topic 16.1)
EvaluationAlways keep a real held-out test set
LicensingCheck terms — some model outputs restrict training competitors
CollapseKeep real data in the loop; never train recursively on pure synth

Used well, synthetic data is one of the highest-leverage tools in modern AI: it turns a labelling budget into a prompt and lets a small team cover cases a large one could not collect. Used carelessly — no real test set, no diversity check, recursive training — it produces models that ace synthetic benchmarks and fail in the world. The discipline is the same as all data work (Topic 18.1): generate deliberately, audit honestly, and measure against reality.

Section 06 ProfessionalExercises

Do these — roughly a weekend
  1. Generate a 500-example text classification set with an LLM. Then cluster it — count how few distinct templates you actually got.
  2. Improve diversity: vary the prompt, raise temperature, seed with real examples. Re-measure the spread.
  3. Train a model on synthetic data, evaluate on a real held-out set, and on a synthetic test set. Compare the two numbers.
  4. Use SMOTE to rebalance an imbalanced tabular dataset (Topic 14.7). Check whether it helps or just inflates the minority class.
  5. Simulate model collapse: train, generate, train on the generation, repeat. Watch the diversity shrink over rounds.
  6. Build a small synthetic evaluation set of deliberately hard, adversarial cases for a task you care about (Topic 19.1).
