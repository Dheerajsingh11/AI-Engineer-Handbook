17.2

AI Coding Assistants

The AI systems that write and understand code — and how to build with them. This page covers how coding assistants work under the hood (it is RAG and agents over a codebase), the spectrum from autocomplete to autonomous agents, why code is a uniquely good fit for AI, how to use these tools well, and the patterns for building your own code-aware features.

Section 01 BeginnerStart from zero

Assumed knowledge

RAG (Phase 4), agents (Phase 8) and tool use (Topic 5.1). AI coding assistants are these applied to code — and a domain you already understand deeply.

AI coding assistants — autocomplete, chat-in-the-editor, and autonomous coding agents — are among the most successful and widely-adopted AI applications. As a software engineer, this is a domain where you have deep intuition, which makes it a great lens for understanding applied AI. And the assistants themselves are built from exactly the components in this handbook.

Why code is a uniquely good fit for AI

Coding assistants work unusually well for reasons worth understanding, because they generalise. Code has structure and rules the model learned from vast public repositories. There is abundant training data (all of open source). And crucially, code has a verifier: you can run it and test it. Unlike an essay, where "correct" is fuzzy, code either compiles and passes tests or it does not — giving the model, and the agent around it, an objective signal to iterate against. That verifiability is why coding agents (Phase 8) can genuinely self-correct: write code, run tests, read the errors, fix, repeat. The general lesson: AI works best where outputs can be automatically verified — look for that property in any problem.

The retrieval problem for code is distinctive. Retrieving relevant code is not quite the same as retrieving prose (Phase 4): you can use the structure — imports, call graphs, type definitions, symbol references — not just embedding similarity. Good code assistants combine semantic search (embeddings of code, Topic 4.2) with structural signals (which functions call this one, what this type is defined as) to assemble the right context. It is hybrid retrieval (Topic 4.6) enriched with the graph structure of the codebase (Topic 12.6) — a nice example of composing several techniques from this handbook for one real problem.

The confident-wrong-code trap

AI-generated code is fluent, plausible, and sometimes subtly wrong — it may use a non-existent API, introduce an off-by-one, or add a security hole, all while looking perfectly reasonable (the hallucination problem, Topic 1.3, in code form). It can also produce code that works but is insecure or does not match your conventions. Treat AI-written code exactly as you would a pull request from a capable but unfamiliar junior engineer: read every line, run the tests, check the security implications, and never merge what you do not understand. The productivity gain is real, but it comes from reviewing faster, not from reviewing less. Blindly accepting AI code is how subtle bugs and vulnerabilities reach production.

Section 04 ProfessionalBuilding code-aware features

You may build code-understanding features into your own products — a documentation assistant, a code-review bot, an internal tool that answers questions about your systems. The patterns:

Migration / refactor toolsAgent with edit + test tools (Phase 8)
Incident / log analysisRAG over logs + reasoning (Topics 4.1, 9.4)
Your engineering background is the advantage here

Building AI-for-code features plays directly to your strengths as a software engineer: you understand codebases, testing, CI/CD, and what developers actually need. The AI part is composition of skills you now have (RAG, agents, tools, evaluation); the domain part — knowing what makes a code-review bot useful, how to safely let an agent edit a repo, what context a developer question really needs — is where your experience makes you better than a pure-ML engineer. This is a concrete example of the roadmap's theme: your existing expertise plus these AI skills is worth more than either alone, and code is the domain where that combination is most obviously valuable.

Section 05 ProfessionalExercises

Do these — roughly a weekend
  1. Use a coding agent on a real task in a repo you know. Note where it excelled and where it produced confident-wrong code.
  2. Build a simple "ask my codebase" RAG tool. Then improve retrieval by adding structural signals (imports, call graph) beyond embeddings.
  3. Build a code-review bot: an agent that reads a diff, checks it against your standards (as a skill, Topic 8.5), and comments.
  4. Give a coding agent test-running as a tool and watch it self-correct on failures (Section 01).
  5. Deliberately accept AI code without review, find the bug it introduced, then establish your review discipline (Section 03).
  6. Write up how your engineering background makes you better at building AI-for-code features (Section 04).
