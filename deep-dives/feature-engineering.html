14.1

Feature Engineering

The craft that quietly decides whether a model works. This page covers turning raw data into features a model can learn from — encoding, scaling, handling missing values, creating and selecting features — why it still matters in the deep-learning era, and the leakage traps that make good offline numbers lie.

Section 01 BeginnerStart from zero

Assumed knowledge

Classical ML (Topic 2.3) and Pandas (Topic 2.2). Feature engineering sits between raw data and a model.

A model does not learn from raw data — it learns from features, the numeric inputs you derive from raw data. Turning "a customer's messy transaction history" into "average spend, days since last purchase, weekend-shopper flag" is feature engineering, and on tabular problems it is often the difference between a mediocre model and a great one.

The saying that holds up

Practitioners repeat it because it keeps being true: "garbage in, garbage out", and its sharper cousin, better features usually beat a better model. On tabular data, a strong feature set with a simple model routinely outperforms a fancy model on raw inputs. The model can only learn from what you give it; feature engineering is deciding what to give it. It is where domain knowledge enters machine learning, and it is often where the real work is.

The words, in plain English
Feature
One input column a model learns from.
Encoding
Turning categories (text labels) into numbers.
Scaling
Putting numeric features on a comparable range.
Imputation
Filling in missing values.
Feature selection
Keeping the useful features, dropping the rest.
Leakage
A feature that secretly contains the answer — the cardinal sin (Topic 2.3).

PythonFeature engineering, done inside a pipeline
from sklearn.compose import ColumnTransformer
from sklearn.preprocessing import StandardScaler, OneHotEncoder
from sklearn.impute import SimpleImputer
from sklearn.pipeline import Pipeline

# Deriving new features from raw columns (domain knowledge here).
df["days_since_purchase"] = (today - df["last_purchase"]).dt.days
df["is_weekend"] = df["order_time"].dt.dayofweek >= 5
df["spend_per_visit"] = df["total_spend"] / df["visit_count"].clip(lower=1)

# Encode/scale/impute INSIDE a pipeline so it is fitted per fold --
# this is what prevents leakage (Section 04, Topic 2.3).
pre = ColumnTransformer([
    ("num", Pipeline([("impute", SimpleImputer(strategy="median")),
                      ("scale",  StandardScaler())]), numeric_cols),
    ("cat", OneHotEncoder(handle_unknown="ignore"), categorical_cols),
])
model = Pipeline([("features", pre), ("clf", classifier)])

Section 03 IntermediateCreating and selecting features

Beyond transforming existing columns, the real leverage is creating features that capture something the model cannot see in the raw data — and then keeping only the ones that help.

Ways to create features
KindExample
Domain-derivedBMI from height & weight; margin from price & cost
Interactionsprice × quantity; age × income
AggregationsAverage order value per customer; count in last 30 days
TemporalRolling means, lags, time-since-event (Topic 14.5)
RatiosClicks per impression; debt-to-income

Then select. More features is not better — irrelevant ones add noise and overfitting risk. Feature selection keeps the useful subset: drop near-constant and highly-correlated columns, use model-based importance (a tree's feature importances, or Lasso's zeroed coefficients from Topic 2.3), or measure each feature's relationship to the target. A tighter, meaningful feature set trains faster, generalises better, and is easier to explain (Topic 16.3).

Section 04 AdvancedDoes it still matter with deep learning?

Deep learning learns its own features (Topic 12.1) — a CNN discovers edge detectors, an LLM learns representations of language. So is manual feature engineering obsolete? The honest answer is it depends on the data.

Where feature engineering matters, by data type
DataFeature engineering…
Tabular (rows & columns)Still crucial — and gradient boosting on good features often beats deep learning
Images, audio, textMostly automatic — the network learns features from raw input
Time seriesBoth — engineered lags/windows plus learned features
Mixed / structured + textEngineer the structured part; embed the text (Topic 4.2)
The tabular reality

For the tabular data that dominates business problems — customers, transactions, sensors, logs — feature engineering plus gradient boosting (Topic 2.3) is still frequently the state of the art, beating deep learning. Deep learning's "it learns its own features" advantage is real for images, audio and text, where raw inputs have rich structure a network can exploit; it is much weaker on tabular data, where hand-crafted features carrying domain knowledge remain decisive. So the skill is far from dead — it is exactly where a lot of applied ML value still lives, and where an engineer who understands the data outperforms one who just throws a big model at it.

The leakage trap, again

The most dangerous feature-engineering mistake is leakage (Topic 2.3): creating a feature that encodes the answer, or fitting a transformation on the whole dataset before splitting. A feature like days_until_cancellation is null exactly for customers who did not cancel — it leaks the target. Target encoding computed over all rows leaks label information into training. The symptom is always the same: brilliant offline numbers, useless in production. Do every transformation inside a pipeline fitted per fold (Section 02), and interrogate any feature that seems too predictive.

Section 05 ProfessionalExercises

Do these — roughly a weekend
  1. Take a raw tabular dataset. Improve a baseline model purely by engineering better features, without changing the model.
  2. Compare one-hot, ordinal and target encoding on a high-cardinality column. Note the accuracy and the leakage risk of target encoding.
  3. Add a "was missing" indicator alongside imputation. Check whether missingness itself is predictive.
  4. Create interaction and ratio features from domain knowledge. Measure their importance in a tree model.
  5. On a Kaggle tabular dataset, compare gradient boosting on good features against a neural network on raw features. Reproduce the Section 04 result.
  6. Deliberately introduce a leaky feature. Watch cross-validation soar, then fix it and see the honest score.
