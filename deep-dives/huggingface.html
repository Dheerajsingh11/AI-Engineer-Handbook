Section 01 BeginnerStart from zero

Assumed knowledge

PyTorch basics (Topic 2.5) and what a model and tokenizer are (Topic 1.3). Hugging Face is the practical layer on top of both.

Hugging Face is the shared infrastructure the open-model world is built on. Nearly every open model (Topic 9.2), dataset and fine-tune passes through it. If open-source AI has a home, this is it — and knowing your way around it is assumed in most AI-engineering roles.

The one class you will use most

AutoModel and AutoTokenizer are the workhorses. Give them a model ID from the Hub and they download the right architecture and tokenizer automatically. Ninety percent of "run this open model" is two from_pretrained calls. The pipeline helper wraps even that for common tasks.

Section 02 BeginnerRun a model in three lines

PythonFrom the Hub to a prediction
from transformers import pipeline

# The pipeline picks the model, tokenizer and task wiring for you.
classifier = pipeline("sentiment-analysis")
classifier("This handbook is genuinely useful.")
# [{'label': 'POSITIVE', 'score': 0.9998}]

# Any task, any model from the Hub -- just name it.
summariser = pipeline("summarization", model="facebook/bart-large-cnn")
embedder   = pipeline("feature-extraction", model="BAAI/bge-small-en-v1.5")

# --- one level down: explicit model + tokenizer (more control) ----
from transformers import AutoModelForCausalLM, AutoTokenizer
import torch

model_id = "meta-llama/Llama-3.2-3B-Instruct"
tok = AutoTokenizer.from_pretrained(model_id)
model = AutoModelForCausalLM.from_pretrained(
    model_id, torch_dtype=torch.bfloat16, device_map="auto")

# Use the model's OWN chat template -- do not hand-format prompts.
messages = [{"role": "user", "content": "Explain RAG in one sentence."}]
inputs = tok.apply_chat_template(messages, add_generation_prompt=True,
                                 return_tensors="pt").to(model.device)
out = model.generate(inputs, max_new_tokens=100)
print(tok.decode(out[0][inputs.shape[1]:], skip_special_tokens=True))
Always use the chat template

Each instruct model expects its prompt wrapped in a specific format (special tokens marking system/user/assistant turns). apply_chat_template applies the model's own format. Hand-formatting the prompt yourself is a common bug that silently degrades quality — the model was trained on its template and behaves worse without it. Let the tokenizer do it.

Section 03 IntermediateDatasets, without running out of memory

PythonLoad, stream, map, split
from datasets import load_dataset

# Load any dataset from the Hub, or your own files.
ds = load_dataset("imdb")                          # {'train': ..., 'test': ...}
ds = load_dataset("json", data_files="my_data.jsonl")

# STREAMING: iterate a dataset far larger than memory (Topic 2.2).
big = load_dataset("HuggingFaceFW/fineweb", streaming=True, split="train")
for example in big.take(1000):
    ...                                            # nothing loaded until asked

# map() applies a function across the dataset, in parallel + cached.
def tokenize(batch):
    return tok(batch["text"], truncation=True, max_length=512)
tokenised = ds.map(tokenize, batched=True, num_proc=4)

# Splitting -- keep an honest held-out set (Topic 2.3).
split = ds["train"].train_test_split(test_size=0.1, seed=42)

Section 04 AdvancedFine-tuning, the Hugging Face way

The libraries you met in Topic 3.5 — PEFT for LoRA, TRL for supervised and preference fine-tuning — are Hugging Face's. They compose with everything above.

PythonLoRA fine-tune, end to end (recap of Topic 3.5)
from peft import LoraConfig, get_peft_model
from trl import SFTTrainer, SFTConfig

peft_config = LoraConfig(r=16, lora_alpha=32, task_type="CAUSAL_LM",
    target_modules=["q_proj", "v_proj"])
model = get_peft_model(model, peft_config)
model.print_trainable_parameters()                 # ~0.5% trainable

trainer = SFTTrainer(
    model=model,
    train_dataset=split["train"], eval_dataset=split["test"],
    processing_class=tok,
    args=SFTConfig(output_dir="./out", num_train_epochs=3,
                   per_device_train_batch_size=4, learning_rate=2e-4,
                   bf16=True, load_best_model_at_end=True),
)
trainer.train()
trainer.save_model("./adapter")                    # ~80 MB, not 14 GB

# Share it back to the Hub in one call.
model.push_to_hub("your-name/llama-3b-support")

Where this fits your stack

You will use Hugging Face mostly for the model and data side: pulling an embedding model or a re-ranker for RAG (Topic 4.2), fine-tuning one on your domain (Topic 3.5), and grabbing datasets. Your application code stays in its own language — you export the resulting model to ONNX and serve it in-process from Java, or stand it behind a vLLM endpoint (Topic 6.1). Think of Hugging Face as the model workshop, not the application runtime: you build and adapt models there, then deploy the artefact into your own stack.

Two practical cautions

Trust. Anyone can upload to the Hub. Prefer models from known organisations, check download counts and the model card, and be wary of loading arbitrary custom code (trust_remote_code=True executes the repo's code on your machine). Gated models. Some models require accepting a licence and authenticating before download — plan for that in automated pipelines.

Section 06 ProfessionalExercises

Do these — roughly a weekend
  1. Run three different tasks with pipeline (sentiment, summarisation, embeddings) in under ten lines total.
  2. Load an instruct model with AutoModel and generate using apply_chat_template. Then deliberately hand-format the prompt instead and compare quality.
  3. Load a dataset in streaming mode and iterate 1,000 examples without loading it all. Confirm flat memory use.
  4. Use map(batched=True) to tokenise a dataset in parallel, then split it with a fixed seed.
  5. Fine-tune a small model with PEFT + TRL on a tiny dataset (recap Topic 3.5). Push the adapter to the Hub.
  6. Build a Gradio demo of your model and deploy it as a Space.
  7. Export a model to ONNX and call it from a non-Python runtime (Topic 6.1).
