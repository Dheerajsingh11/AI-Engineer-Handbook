Decoding & Sampling

The knobs you turn at generation time. This page covers decoding and sampling — temperature, top-k, top-p (nucleus) and friends — how each one reshapes the probability distribution the model produces, why the same prompt can be factual or creative depending only on these settings, and the presets that actually work.

Section 01 BeginnerStart from zero

Assumed knowledge

How an LLM predicts the next token (Topic 1.3) and softmax (Topic 1.2). This page is the layer on top: once the model gives a distribution, how do you pick a token from it?

An LLM does not output a word. At each step it outputs a probability distribution over every possible next token (via softmax, Topic 1.3). Decoding is the rule that turns that distribution into an actual chosen token — and the settings that control it (temperature, top-k, top-p) are the difference between a dry, repetitive answer and a fluent, creative one. Same model, same prompt: the decoding settings alone can change everything.

Why this matters as much as the prompt

Practitioners obsess over prompts and forget that generation settings are the other half of the interface. A model set to temperature 0 is deterministic and terse — right for extraction, classification and code. The same model at temperature 1.0 with top-p 0.95 is fluent and varied — right for chat and brainstorming. If your outputs are too repetitive, too random, or won't stop, the fix is often here, not in the prompt or the model. These are the temperature, top_k, top_p arguments you have already seen in every generate() call.

The words, in plain English
Logits
The raw per-token scores before softmax turns them into probabilities.
Greedy
Always take the single most likely token. Deterministic.
Sampling
Draw a token at random according to the probabilities. Varied.
Temperature
A dial that sharpens or flattens the distribution before sampling.
Top-k
Only consider the k most likely tokens.
Top-p (nucleus)
Only consider the smallest set of tokens whose probability adds up to p.

Section 02 IntermediateTemperature

Temperature is the single most important knob. It divides the logits before softmax, which reshapes the distribution — without changing which token is most likely.

Softmax with temperature T pi = exp(zi / T)∑j exp(zj / T) zi are the logits. T < 1 sharpens the distribution (the top token gets even more probability → more deterministic, more focused). T > 1 flattens it (rare tokens get a chance → more random, more creative). T = 1 leaves it unchanged. As T → 0 it becomes argmax — pure greedy decoding.
What temperature does, concretely
TemperatureEffectUse for
0 (greedy)Always the top token; fully deterministicExtraction, classification, code, tool calls
0.2–0.5Mostly focused, slight variationFactual Q&A, RAG answers
0.7–0.9Balanced fluency and varietyGeneral chat — the common default
1.0–1.3Adventurous, more surprisingBrainstorming, creative writing
Temperature alone is a blunt instrument

Raising temperature to get variety also raises the chance of sampling a genuinely bad token from the long tail of the distribution — a nonsense word, a topic swerve. High temperature with no truncation is how you get fluent-sounding garbage. That is exactly the problem the next section's samplers solve: cut off the tail first, then apply temperature. In practice you almost never use temperature by itself — you pair it with top-p or top-k.

Section 03 IntermediateTop-k, top-p & min-p

Truncation samplers throw away the unlikely tokens before sampling, so you get variety among good options without risking the garbage in the tail.

The truncation samplers
SamplerRuleCharacter
Top-kKeep the k highest-probability tokens, renormalise, sampleFixed number of candidates (e.g. k=40)
Top-p (nucleus)Keep the smallest set whose probabilities sum to p, sampleAdapts: few candidates when confident, many when unsure
Min-pKeep tokens with prob ≥ min_p × (top token's prob)Threshold scales with confidence; newer, robust at high temp
Why top-p usually beats top-k

The weakness of top-k is that k is fixed. When the model is very sure (one obvious next word), k=40 still forces 39 worse options into consideration. When it is genuinely uncertain (many valid continuations), k=40 may cut off good ones. Top-p fixes this by keeping a dynamic number of tokens — the "nucleus" of probability mass. If the top token already has 0.92 probability, top-p 0.9 keeps just that one; if probability is spread thin, it keeps many. It adapts to the model's confidence at each step, which is why top-p (0.9–0.95) is the common default, often with a safety-net top-k. Min-p is a newer take that sets the cut relative to the most likely token, and holds up better at high temperatures.

PythonThe knobs, in a Hugging Face generate() call
out = model.generate(
    **inputs,
    do_sample=True,          # False = greedy (ignores temperature/top-p)
    temperature=0.7,         # reshape the distribution (Section 02)
    top_p=0.9,               # nucleus: keep the top 90% mass (Section 03)
    top_k=50,                # safety net: never more than 50 candidates
    repetition_penalty=1.15, # discourage repeating tokens (Section 04)
    no_repeat_ngram_size=3,  # hard-block any repeated 3-gram
    max_new_tokens=200,      # length cap
    eos_token_id=tok.eos_token_id,   # STOP when the model emits <eos>
)
# Order of operations: top-k/top-p filter the tokens, temperature reshapes,
# then one token is sampled. (Exact order varies slightly by library.)

Section 04 AdvancedGreedy, beam, penalties & stopping

The rest of the generation controls
ControlWhat it does
Greedy / do_sample=FalseAlways the top token. Deterministic, but often bland and loop-prone
Beam searchTrack several candidate sequences, keep the best. Good for translation; rarely used for chat — tends to be bland and repetitive
Repetition penaltyDown-weights tokens already generated — fixes "the the the" loops (values ~1.1–1.3)
No-repeat-ngramHard-bans any n-gram from repeating — a blunt loop-breaker
Presence / frequency penaltyOpenAI-style knobs that penalise repeated topics/tokens
SeedFixes the RNG so sampling is reproducible (vital for evals, Topic 19.1)
Stop sequences / eosWhere generation ends — an emitted <eos> or a matched stop string
The three things that fix "it won't stop / it repeats"

These are the exact symptoms of a weak or small model (Topic 9.5), and the cures live here. Won't stop? The model never learned to emit <eos> (often because training data had no document boundaries, Topic 18.1) — add a stop sequence and always pass eos_token_id. Repeats/loops? Add repetition_penalty (~1.15) and no_repeat_ngram_size=3, and prefer sampling over greedy. Too random/incoherent? Lower temperature and tighten top-p. For a local model in Ollama these same knobs live in the Modelfile as PARAMETER temperature, PARAMETER stop, etc. (Topic 19.4).

Section 05 ProfessionalA note on checkpoints

A different knob you will meet constantly, easy to confuse because the word does double duty. There are two kinds of "checkpoint," and they have nothing to do with each other.

The two "checkpoints"
TermWhat it isWhy
Model checkpointA saved snapshot of the weights during training (e.g. every epoch: checkpoint-313/)Resume after a crash; keep the best checkpoint by validation loss, not the last (Topic 19.1)
Gradient checkpointingA memory trick: don't store all activations in the forward pass — recompute them during backpropTrades compute for VRAM so a bigger model/batch fits on your GPU (Topics 2.6, 9.6)
Keep the best, not the last

The single most useful habit with model checkpoints: save periodically and select by validation performance, not by whichever ran last. A model often peaks partway through training and then overfits — so the final checkpoint can be worse than one from the middle (Topic 19.1). Frameworks make this one flag (save_strategy, load_best_model_at_end, save_total_limit to avoid a pile of folders). Gradient checkpointing is unrelated — it is purely a way to fit training in memory, at the cost of ~20–30% more compute (Topic 2.6). They share a name and nothing else.

Section 06 ProfessionalExercises

Do these — feel each knob
  1. Take one prompt. Generate at temperature 0, 0.7, and 1.3 (top-p 1.0). Watch it go from rigid to unhinged.
  2. Fix temperature at 1.0 and sweep top-p from 1.0 down to 0.5. See the tail of bad tokens get cut off.
  3. Compare top-k=40 vs top-p=0.9 on a prompt where the model is very confident, and one where it is unsure. Note where each struggles.
  4. Reproduce a "won't stop" failure with a small model, then fix it with a stop sequence and eos_token_id.
  5. Trigger a repetition loop (low temp, greedy), then fix it with repetition_penalty and no_repeat_ngram_size.
  6. Set a seed and generate twice — confirm identical output. This is what makes an eval reproducible (Topic 19.1).
