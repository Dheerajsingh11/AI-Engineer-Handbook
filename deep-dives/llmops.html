Section 01 BeginnerStart from zero

Assumed knowledge

Evaluation metrics from Topics 1.2 and 4.7. Standard observability practice — metrics, traces, dashboards.

LLMOps is DevOps applied to systems whose output is a sample from a distribution rather than a value. Most of your practice carries over. Three things genuinely change.

What is different from ordinary services
ConcernOrdinary serviceLLM system
CorrectnessassertEqualsNo single right answer. Graded, statistical evaluation
Regression sourceYour code changedYour code, your prompt, or the provider's model — and you were not told
CostRoughly fixed per instancePer request, highly variable, unbounded without limits
LatencyMilliseconds, tight distributionSeconds, long tail, driven by output length
DebuggingRead the stack traceRead the prompt, the retrieved context, and the reasoning
The question that drives everything on this page

A user reports a bad answer three days ago. Can you reconstruct exactly what happened — the resolved prompt, the prompt version, the model and its version, the sampling parameters, the retrieved chunk ids and their scores, every tool call and result, the tokens and the cost?

If not, you cannot debug it, you cannot tell whether your fix worked, and you cannot tell whether it recurs. Everything else in LLMOps is downstream of being able to answer that question.

Order your assertions by cost, not by sophistication

Schema validity, required fields, citation presence, latency and cost budgets are deterministic, instant, free and never flaky. Run them on every case. LLM-as-judge assertions are slow, expensive and themselves noisy — reserve them for the dimensions rules genuinely cannot capture.

Most teams reach for the judge first, end up with a suite that takes twenty minutes and fails randomly, and stop trusting it within a month. A fast deterministic core with a small judged layer on top is what survives contact with a busy team.

JavaDeterministic evaluation in the JUnit suite you already run
@SpringBootTest
class TriageEvaluationTest {

    @Autowired TriageService triage;

    static Stream<GoldenCase> goldenSet() throws IOException {
        // Versioned with the code, reviewed in pull requests.
        return objectMapper.readValue(
                new ClassPathResource("evals/triage-golden.json").getFile(),
                new TypeReference<List<GoldenCase>>() {}).stream();
    }

    @ParameterizedTest
    @MethodSource("goldenSet")
    void meetsContract(GoldenCase testCase) {
        var result = triage.triage(testCase.input());

        // Deterministic assertions: fast, free, never flaky.
        assertThat(result.category()).isEqualTo(testCase.expectedCategory());
        assertThat(result.severityOneToFive()).isBetween(1, 5);
        assertThat(result.summary()).hasSizeLessThan(200);

        // Tolerance where the output is genuinely graded.
        assertThat(result.severityOneToFive())
                .isCloseTo(testCase.expectedSeverity(), within(1));
    }

    @Test
    void passRateExceedsBaseline() {
        var cases = goldenSet().toList();
        long passed = cases.stream().filter(this::passes).count();
        double rate = (double) passed / cases.size();

        // A confidence interval, so you do not fail the build on noise.
        double se = Math.sqrt(rate * (1 - rate) / cases.size());
        double lowerBound = rate - 1.96 * se;

        assertThat(lowerBound)
                .as("pass rate %.3f (95%% lower bound %.3f)", rate, lowerBound)
                .isGreaterThan(0.85);
    }
}

Section 03 AdvancedObservability

JavaA span tree that answers the incident question
@Component
class ObservabilityAdvisor implements CallAdvisor {

    private final Tracer tracer;
    private final MeterRegistry meters;

    @Override public int getOrder() { return 100; }   // after redaction

    @Override
    public ChatClientResponse adviseCall(ChatClientRequest request,
                                         CallAdvisorChain chain) {
        var span = tracer.nextSpan().name("gen_ai.chat").start();

        try (var scope = tracer.withSpan(span)) {
            // OTel GenAI semantic conventions: these exact attribute
            // names mean your spans work with everyone else's tooling.
            span.tag("gen_ai.system", "anthropic");
            span.tag("gen_ai.request.model", modelId(request));
            span.tag("gen_ai.request.temperature", String.valueOf(temperature(request)));

            // Business identity: what makes a trace searchable when a
            // customer complains three days later.
            span.tag("app.tenant_id", currentTenant());
            span.tag("app.prompt_version", promptVersion(request));
            span.tag("app.conversation_id", conversationId(request));

            var response = chain.nextCall(request);

            var usage = response.chatResponse().getMetadata().getUsage();
            span.tag("gen_ai.usage.input_tokens",  String.valueOf(usage.getPromptTokens()));
            span.tag("gen_ai.usage.output_tokens", String.valueOf(usage.getCompletionTokens()));
            span.tag("gen_ai.response.finish_reason", finishReason(response));

            double cost = pricing.cost(modelId(request), usage);
            span.tag("app.cost_usd", String.format("%.6f", cost));

            meters.counter("gen_ai.tokens", "type", "output",
                           "model", modelId(request)).increment(usage.getCompletionTokens());
            meters.summary("gen_ai.cost", "tenant", currentTenant()).record(cost);

            return response;

        } catch (Exception e) {
            span.error(e);
            throw e;
        } finally {
            span.end();
        }
    }
}

Logging prompts is a privacy decision, not a debugging one

Full prompts and completions are the most useful thing to log and the most dangerous. They contain customer data, retrieved documents and sometimes credentials users pasted in.

A workable policy: log prompts in full in development; in production log a hash plus the prompt version, with full content behind a redaction advisor, a shorter retention period and access controls. Store retrieved chunk ids rather than chunk text — you can look the text up, and ids are not personal data. This connects to §6.4.

Section 04 AdvancedPrompt versioning and safe rollout

JavaVersioned prompts with canary routing
@Service
class PromptRegistry {

    // A prompt is only correct WITH RESPECT TO a model version and
    // its parameters. Version them together or you will chase ghosts.
    public record PromptVersion(
            String id, String version, String template,
            String validatedAgainstModel, double temperature,
            Instant createdAt, String createdBy,
            double goldenSetPassRate) {}

    public PromptVersion resolve(String promptId, String tenantId) {
        var active = repository.activeVersion(promptId);
        var canary = repository.canaryVersion(promptId);

        if (canary == null) return active;

        // Deterministic assignment by tenant hash: a tenant always
        // sees the same version, so their experience is consistent
        // and the comparison is not polluted by within-user switching.
        int bucket = Math.floorMod(tenantId.hashCode(), 100);
        return bucket < canary.trafficPercent() ? canary.version() : active;
    }
}

@Component
class CanaryEvaluator {

    @Scheduled(cron = "0 */15 * * * *")
    public void compare() {
        for (var canary : registry.activeCanaries()) {
            var control = metrics.window(canary.promptId(), canary.controlVersion(),
                                         Duration.ofHours(6));
            var variant = metrics.window(canary.promptId(), canary.version(),
                                         Duration.ofHours(6));

            // Guardrails first: roll back immediately on a hard regression,
            // without waiting for statistical significance.
            if (variant.errorRate() > control.errorRate() * 1.5
                || variant.p95Latency() > control.p95Latency() * 2
                || variant.costPerRequest() > control.costPerRequest() * 1.5) {
                registry.rollback(canary);
                alerts.page("canary rolled back: " + canary.promptId());
                continue;
            }

            // Then quality, with an interval -- do not promote on noise.
            if (variant.sampleSize() > 500
                && variant.satisfactionLowerBound() > control.satisfaction()) {
                registry.promote(canary);
            }
        }
    }
}
Pin your model version

Calling a floating alias means the provider can change the model underneath you. Your prompts were tuned against specific behaviour; a new version can change output length, formatting, refusal boundaries and tool-calling reliability, and your golden set will start failing for reasons that are nowhere in your git history.

Pin an explicit dated version. Treat a model upgrade as a deployment: run the golden set against the new version, diff the results, canary it, and keep the old version available for rollback. Subscribe to provider deprecation notices — pinned versions do eventually retire, and you want that on your schedule.

The feedback loop that keeps the system honest

Capture a signal on every response — explicit thumbs, or implicit ones like whether the user rephrased, escalated to a human, or copied the answer. Weekly, sample the negative cases, have someone label the correct behaviour, and add them to the golden set.

Your offline suite then converges on the failures that actually occur rather than the ones you imagined when you built it. Without this loop the golden set decays into a test of last year's problems, and the pass rate stays reassuringly high while users grow unhappier.

Section 06 ProfessionalExercises

Do these — roughly a weekend
  1. Take a bad answer from your own system and try to reconstruct exactly what produced it. Note every piece of information you wish you had logged.
  2. Instrument one call path with OTel GenAI attributes. View the trace and confirm you could now answer exercise 1.
  3. Build a golden-set JUnit test that fails the build on regression, using a confidence interval rather than a bare threshold.
  4. Externalise a prompt into a versioned file with its model and parameters recorded. Deploy a change without touching Java code.
  5. Implement canary routing by tenant hash. Verify a tenant consistently receives the same version.
  6. Build the cost dashboard broken down by tenant and feature. Find your most expensive endpoint — it is rarely the one you expect.
  7. Deliberately switch to a different model version and run your golden set. Record what changed, and how you would have detected it in production.
  8. Implement a redaction advisor and verify no PII reaches your logs while prompt versions still do.
