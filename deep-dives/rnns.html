12.2

RNNs, LSTMs & Sequence Models

How networks handled sequences before transformers — and why the transformer replaced them. This page explains the recurrent idea (a hidden state carried through time), why plain RNNs forget, how LSTMs and GRUs fixed it with gates, the killer limitation that opened the door to attention, and where recurrence still lives.

Section 01 BeginnerStart from zero

Assumed knowledge

Neural network basics (Topic 2.4). This page is best read as the prequel to attention (Topic 1.3) — it explains the problem the transformer solved.

A plain neural network (Topic 2.4) takes a fixed-size input and produces an output. But language, audio and time-series are sequences of varying length, where order matters and each element depends on what came before. "The film was not good" and "not, the film was good" contain the same words and opposite meanings. You need an architecture that processes things in order and remembers.

The recurrent idea

A recurrent neural network processes a sequence one element at a time, carrying a hidden state — a summary of everything seen so far — from each step to the next. At each step it combines the new input with the running memory to produce a new memory. That loop, the same small network applied repeatedly with a memory passed along, is the entire idea. It let neural networks handle language and time long before transformers, and it dominated sequence modelling from roughly 2014 to 2017.

The words, in plain English
Sequence
An ordered list where position matters: words, audio samples, daily prices.
Hidden state
The RNN's running memory — a vector summarising the sequence so far.
Recurrent
Applying the same network repeatedly, feeding its own output back in.
Timestep
One position in the sequence being processed.
Gate
A learned valve (in LSTMs/GRUs) that decides what to keep, forget or output.
Vanishing gradient
Signal fading over many steps, so the network cannot learn long-range links (Topic 1.4).

Section 02 IntermediateThe recurrence, and why plain RNNs forget

The RNN update ht  =  tanh( Wh ht−1 + Wx xt + b ) New memory ht is a blend of the previous memory ht−1 and the current input xt, squashed by tanh. The same weights W are reused at every step — that weight-sharing is what lets one network handle any length, exactly as a CNN reuses one filter across space (Topic 12.1).
PythonAn RNN forward pass, by hand
import numpy as np

def rnn_forward(inputs, Wx, Wh, b):
    h = np.zeros(Wh.shape[0])          # memory starts empty
    states = []
    for x in inputs:                   # one timestep at a time, IN ORDER
        h = np.tanh(Wx @ x + Wh @ h + b)   # blend input with memory
        states.append(h)
    return states                      # h at every step; last one summarises all
# The final h is a fixed-size summary of a variable-length sequence.
Why plain RNNs cannot remember far back

The hidden state is overwritten at every step, and the training signal must travel back through every step to reach the beginning (backpropagation through time). Over long sequences that signal shrinks toward zero — the vanishing gradient problem (Topic 1.4) — so the network cannot learn dependencies more than a handful of steps apart. In practice a plain RNN forgets the start of a long sentence by the time it reaches the end. "The cat, which had been missing for days and worried the whole family, was finally found" — linking "cat" to "was" across all that is exactly what a plain RNN fails at.

Section 03 IntermediateLSTMs and GRUs: memory with gates

The fix, and what made RNNs genuinely useful, was to add gates: small learned networks that decide what to keep, what to throw away, and what to output. An LSTM maintains a protected cell state that information can travel along largely undisturbed — a memory highway that sidesteps the vanishing-gradient problem.

The LSTM gates
GateDecides
Forget gateWhat to erase from the cell memory
Input gateWhat new information to write in
Output gateWhat of the memory to expose as this step's output

GRU is a streamlined LSTM with two gates instead of three — fewer parameters, often just as good. Both were the workhorses of sequence modelling for years: machine translation, speech recognition, text generation and time-series forecasting all ran on LSTMs before 2017. If you read pre-transformer NLP or work with older systems, LSTMs are what you will find. The key takeaway is why gates helped: they let the network learn to protect important information across many steps instead of blindly overwriting its memory.

Section 04 AdvancedThe limitation that opened the door to transformers

LSTMs solved the memory problem but carried a deeper one that no amount of gating could fix — and that limitation is precisely what the transformer removed.

Sequential processing cannot be parallelised

An RNN must process step 2 after step 1, because step 2 needs step 1's hidden state. This is inherent to recurrence — and it is a disaster for modern hardware. GPUs are massively parallel (Topic 11.2), but an RNN forces the computation into a strict sequence, leaving most of the GPU idle. Training on long sequences and huge datasets became painfully slow. The transformer (Topic 1.3) replaced recurrence with attention, which looks at all positions at once — fully parallel, and with a direct connection between any two positions no matter how far apart. That removed both the speed ceiling and the last of the long-range memory problem in one move. It is why transformers, not LSTMs, scaled to the models we have today.

RNN/LSTM vs transformer
RNN / LSTMTransformer
ProcessingSequential (one step at a time)Parallel (all positions at once)
Long-range linksHard, even with gatesDirect, any distance (attention)
Training speed at scaleSlow — GPU underusedFast — GPU saturated
Memory of contextA fixed-size state (a bottleneck)The whole context, always visible

Section 05 ProfessionalWhere recurrence still lives

Transformers won for large-scale language, but recurrence is not dead — and it is quietly returning.

Recurrence today
WhereWhy still used
Small / edge devicesCheaper than attention; fine for short sequences
Streaming / real-timeNaturally processes one element at a time
Some time-series forecastingStrong, efficient baselines
Modern state-space models (Mamba, RWKV)Recurrent-style, but parallelisable — linear scaling with length, unlike attention's quadratic

The interesting turn. Attention's cost grows quadratically with sequence length (Topic 1.3), which makes very long contexts expensive. A new class of state-space models (Mamba, RWKV) revives the recurrent idea — a state carried through the sequence — but restructured so it can be trained in parallel and scales linearly with length. They are a live research direction for exactly the long-context problem where transformers struggle. The recurrent idea you learned here is not a museum piece; it is being reinvented. For your day-to-day work you will use transformers, but knowing the recurrent lineage helps you understand both where the field came from and where it may go next.

Section 06 ProfessionalExercises

Do these — roughly an evening
  1. Implement rnn_forward and feed it a sequence. Confirm the final hidden state changes when you reorder the inputs — order matters.
  2. Train a small LSTM in PyTorch to classify sentiment on short reviews. It will work; note where it struggles on long ones.
  3. Construct a long-range dependency task (predict a token that depends on one 50 steps back). Show a plain RNN fails and an LSTM does better.
  4. Compare training speed of an LSTM and a small transformer on the same sequence data. Observe the parallelism gap from Section 04.
  5. Read the abstract of the Mamba paper. Explain in a sentence how it keeps recurrence's memory but recovers parallel training.
