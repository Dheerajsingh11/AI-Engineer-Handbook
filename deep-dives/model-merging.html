18.5

Model Merging

Combining models without training. This page covers model merging — blending the weights of several fine-tuned models into one that inherits their skills, for the price of arithmetic instead of a GPU run — the methods (soups, SLERP, TIES, task arithmetic), the maths of task vectors, and when it works versus when it quietly ruins the model.

Section 01 BeginnerStart from zero

Assumed knowledge

Fine-tuning (Topic 3.5) and that a model is a big bag of weight numbers (Topic 2.4). This page does something surprising with those numbers: averages them.

Suppose you have two fine-tuned models — one good at coding, one good at medical Q&A — both fine-tuned from the same base. Could you get a model good at both without training a new one? Astonishingly, often yes: you can merge their weights directly. Model merging combines several models into one by arithmetic on their parameters, no training data and no GPU training run required — just a few minutes of maths.

Why this even works

It sounds like it should produce garbage — averaging two neural networks? — but it works because the models being merged are all fine-tuned from the same base. They start from the same point in weight-space and each moves only a short distance to specialise, so their weights stay "compatible." Averaging those nearby points lands somewhere that keeps much of each one's skill. Merge models from different bases and you do get garbage — the compatibility is the whole trick. It is one of the cheapest ways to combine capabilities in modern AI, which is why so many top open models on the leaderboards are merges.

The words, in plain English
Model soup
Simply averaging the weights of several models.
Task vector
The difference a fine-tune made: (fine-tuned weights − base weights).
Task arithmetic
Adding/subtracting task vectors to add or remove skills.
SLERP
Spherical interpolation — a smarter "average" that respects weight geometry.
TIES / DARE
Merge methods that resolve conflicts between models before combining.

Section 02 IntermediateThe simplest merge: averaging

The most basic method — a model soup — is exactly what it sounds like: take several models and average their weights element-wise.

Weight averaging (model soup) θmerged = 1N ∑i=1N θi θi are the weight tensors of the N models (all same architecture, same base). Average them parameter-by-parameter and you often get a model as good as, or better than, any single one — especially when averaging several fine-tunes of the same model trained with different seeds or hyperparameters. Free robustness, no training.

Section 03 IntermediateTask vectors & task arithmetic

A more powerful view: a fine-tune is a direction in weight-space — the task vector, the difference between the fine-tuned and base weights. And you can do arithmetic with those directions.

Task arithmetic τtask = θfine-tuned − θbase   (the "skill" as a vector) θnew = θbase + λ₁τA + λ₂τB − λ₃τC Add task vectors to combine skills (A and B), and — remarkably — subtract one to remove a behaviour (e.g. subtract a "toxicity" task vector to make a model less toxic). The scalars λ weight each skill. Capabilities become things you can add and remove like ingredients.
The merge methods, roughly in order of sophistication
MethodWhat it adds over plain averaging
Model soup (average)Nothing — the baseline; great for merging same-task fine-tunes
SLERPInterpolate along the sphere, not the straight line — respects weight geometry (2 models)

TIES-mergingTrim tiny changes and resolve sign conflicts before merging many models
DARERandomly drop and rescale task-vector entries to reduce interference

Section 04 AdvancedWhy the fancy methods exist

Plain averaging breaks down when models disagree. Two task vectors can push the same weight in opposite directions; naive averaging cancels them out and loses both skills. The advanced methods exist to handle exactly this interference.

The interference problem, and the fix

When merging many models, their task vectors conflict: for a given parameter, model A wants it larger and model B wants it smaller. Average them and you get the middle — satisfying neither, degrading both. TIES-merging tackles this in three steps: trim each task vector to only its largest changes (most are noise), elect a sign for each parameter by which direction has more total magnitude, and merge only the agreeing entries. DARE takes a different angle: randomly zero most task-vector entries and rescale the rest, which thins out the conflicts before merging. Both let you combine more models with less mutual damage than plain averaging — which is why they dominate the recipes behind merged open models.

The rules that keep merges from being garbage

Merging is cheap but not magic. Same base, same architecture: you can only merge models that share a lineage and shape — different bases produce nonsense. It is not additive forever: merge too many conflicting skills and quality collapses; each addition can erode others. Evaluate, always: a merge can look plausible and be quietly worse on the tasks that matter — so measure the merged model on a real eval set (Topic 19.1) before trusting it, exactly as you would a fine-tune. Merging replaces a training run, not the measurement.

Section 05 ProfessionalWhere it fits

A cheap tool in the model-building kit

Model merging earns its place because it is almost free. Averaging a few fine-tunes of your own model (a "soup") is a no-cost way to get a more robust, less seed-dependent result. Task arithmetic lets you compose capabilities — or strip an unwanted behaviour — without any data. And tools like mergekit make TIES/DARE/SLERP recipes a short config file, running on CPU in minutes. It pairs naturally with LoRA fine-tuning (Topic 3.5): fine-tune several specialised adapters, then merge. Treat it as a low-cost experiment worth trying before committing to another training run — it frequently gives you a better model for the price of some matrix addition, and it is a genuinely useful trick most engineers have never heard of.

Section 06 ProfessionalExercises

Do these — average some models
  1. Fine-tune the same base model twice with different seeds. Average the weights (a soup) and check it beats either alone.
  2. Compute a task vector (fine-tuned − base). Add it to the base at scales λ = 0.5, 1.0, 1.5 and watch the skill strengthen then break.
  3. Try to remove a behaviour by subtracting its task vector; evaluate whether it worked without wrecking the rest.
  4. Use mergekit to TIES-merge three fine-tunes. Compare it to naive averaging on each model's own task.
  5. Merge two models from different bases and confirm it produces garbage — feel why shared lineage matters.
  6. Evaluate every merge on a held-out set (Topic 19.1). Prove to yourself that "looks fine" is not "is fine."
