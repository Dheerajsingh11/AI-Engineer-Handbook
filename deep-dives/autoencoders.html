Autoencoders & VAEs

Learning to compress, and learning to generate. This page explains autoencoders — networks that squeeze data through a bottleneck and rebuild it — why that forces them to learn what matters, how variational autoencoders turn the idea into a generator, and where the pattern shows up in anomaly detection, embeddings and the latent space that modern image generators run in.

Section 01 BeginnerStart from zero

Assumed knowledge

Neural network basics (Topic 2.4) and the idea of an embedding (Topic 1.1). Autoencoders are a clean introduction to how networks learn compressed representations.

An autoencoder is a neural network trained to do something that sounds pointless: reproduce its own input. Feed it an image, it outputs the same image. The trick is what sits in the middle — a bottleneck, a layer much smaller than the input. To rebuild the image after squeezing it through that bottleneck, the network must learn to keep only what matters and discard the rest.

The two halves
PartDoes
EncoderCompresses the input into a small vector (the "latent" or "code")
BottleneckThe small vector — a learned compression of the input
DecoderRebuilds the original from that small vector
Why reproducing the input is not pointless

Because of the bottleneck, the network cannot just copy — there is not enough room. To reconstruct a face from, say, 32 numbers, those 32 numbers must capture the essence of the face: pose, features, expression. The autoencoder is forced to discover a compact, meaningful representation of the data, with no labels — pure unsupervised learning. That learned code is a general-purpose embedding (Topic 1.1), and the reconstruction task is just a clever way to train one.

The words, in plain English
Latent space
The space of small codes the encoder produces — a compressed map of the data.
Bottleneck
The narrow middle layer that forces compression.
Reconstruction
The decoder's attempt to rebuild the input; its error is the training signal.
Encoder / decoder
The compress and rebuild halves.
Variational (VAE)
A version whose latent space is smooth, so you can generate new data from it.

Section 02 IntermediateA simple autoencoder

PythonEncoder + bottleneck + decoder in PyTorch
import torch.nn as nn

class Autoencoder(nn.Module):
    def __init__(self, input_dim=784, latent_dim=32):
        super().__init__()
        self.encoder = nn.Sequential(
            nn.Linear(input_dim, 128), nn.ReLU(),
            nn.Linear(128, latent_dim))          # 784 -> 32: the squeeze
        self.decoder = nn.Sequential(
            nn.Linear(latent_dim, 128), nn.ReLU(),
            nn.Linear(128, input_dim))           # 32 -> 784: rebuild

    def forward(self, x):
        z = self.encoder(x)                      # the compressed code
        return self.decoder(z), z

# Training: minimise the RECONSTRUCTION error. No labels needed --
# the target IS the input. That is what makes it unsupervised.
# loss = mse(reconstruction, x)   (Topic 2.4)

Section 03 AdvancedFrom compression to generation: the VAE

A plain autoencoder can rebuild inputs it has seen, but its latent space is full of holes — pick a random code and the decoder produces garbage. The variational autoencoder fixes this and turns the autoencoder into a generator.

The VAE idea

Instead of encoding an input to a single point, a VAE encodes it to a small distribution (a mean and a spread), and trains the latent space to be smooth and continuous — every nearby point decodes to something plausible. Two consequences follow: you can sample a random point and generate new, realistic data, and you can move smoothly between two inputs in latent space (interpolate one face into another). By forcing the latent space to be well-organised, the VAE makes generation possible. It was one of the first successful deep generative models, and the "encode to a compact, smooth latent space, then decode" pattern is everywhere.

PythonWhat makes a VAE different
# The encoder outputs a mean AND a spread, not a single code.
mu, logvar = encoder(x)
z = mu + torch.exp(0.5 * logvar) * torch.randn_like(mu)   # sample
reconstruction = decoder(z)

# Two loss terms balance reconstruction against a smooth latent space:
recon_loss = mse(reconstruction, x)              # rebuild accurately...
kl_loss    = kl_divergence(mu, logvar)           # ...AND keep latent tidy (Topic 1.2)
loss = recon_loss + kl_loss

# Now sampling a random z and decoding produces NEW plausible data.
new_sample = decoder(torch.randn(latent_dim))

Section 04 ProfessionalWhere the pattern shows up

You will rarely build an autoencoder from scratch in AI-engineering work, but the encode-to-latent pattern is load-bearing across the field.

The autoencoder pattern in the wild
UseHow
EmbeddingsThe encoder's compressed code is a learned representation (Topic 1.1)
Anomaly detectionTrain on normal data; anything it reconstructs badly is anomalous (its own topic)
Dimensionality reductionA non-linear alternative to PCA (Topic 1.1)
Denoising / restorationRebuild clean data from corrupted input
Latent diffusionModern image generators (Topic 12.5) run diffusion in an autoencoder's compressed latent space, not on raw pixels — far cheaper
The connection to modern image generation

The most important place this pattern appears today is latent diffusion, the technique behind Stable Diffusion and its relatives (Topic 12.5). Generating a high-resolution image pixel by pixel is enormously expensive. Instead, these systems use an autoencoder to compress images into a small latent space, run the whole (costly) diffusion process in that compact space, and then decode back to a full image at the end. The autoencoder is what makes state-of-the-art image generation computationally feasible. So this "toy" architecture is a core component of one of the most impressive generative systems — a good reminder that foundational ideas compound.

Section 05 ProfessionalExercises

Do these — roughly an evening
  1. Train the plain autoencoder on MNIST. Compare inputs and reconstructions — note what detail the bottleneck loses.
  2. Shrink the latent dimension from 32 to 2 and back to 128. Observe how reconstruction quality tracks bottleneck size.
  3. Train a VAE. Sample random latent points and decode them — confirm you get new, plausible digits (a plain AE will not).
  4. Interpolate between two inputs in the VAE's latent space. Watch one digit morph smoothly into another.
  5. Build a denoising autoencoder: add noise to inputs, train it to output the clean version.
  6. Use a trained autoencoder for anomaly detection: flag inputs with high reconstruction error.
