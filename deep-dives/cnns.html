CNNs & Computer Vision

The architecture that made computers see. This page explains the one idea behind convolutional networks — that the same small pattern-detector should slide across the whole image — builds a convolution by hand, covers the CNN toolkit (pooling, channels, stride) and the task taxonomy (classification, detection, segmentation), and places CNNs against the vision transformers that now rival them.

Section 01 BeginnerStart from zero

Assumed knowledge

Neural network basics (Topic 2.4) and what a matrix is (Topic 1.1). Computer vision is where deep learning first broke through (Topic 11.2).

A photo is just a grid of numbers — each pixel a brightness value, three of them for colour. So why not feed that grid to an ordinary neural network (Topic 2.4)? You can, and it works badly, for two reasons that the whole design of a CNN exists to fix.

Why a plain network is wrong for images
ProblemConsequence
Too many connectionsA 1000×1000 image has a million inputs; connecting every one to every neuron is billions of weights — unlearnable
No sense of placeA plain network treats pixel (0,0) and its neighbour as unrelated; it has no notion that nearby pixels form shapes
No translation invarianceA cat in the top-left and the same cat in the bottom-right look completely different to it
The one idea behind CNNs

A feature that is useful in one part of an image is useful everywhere, so learn it once and slide it across the whole image. An edge detector that works in the corner works in the centre too — so instead of separate weights per position, a CNN learns a small filter (a tiny pattern-detector) and applies the same filter across every location. This slashes the number of weights and builds in the idea that images are made of local patterns that can appear anywhere. That single principle — shared, sliding filters — is what a convolution is.

The words, in plain English
Convolution
Sliding a small filter across an image, computing a match at each position.
Filter / kernel
The small grid of learned weights that detects one pattern (an edge, a texture).
Feature map
The output of one filter across the image — where that pattern was found.
Channel
One layer of the input or output; a colour image has 3 input channels.
Pooling
Shrinking a feature map by summarising small regions — keeps the gist, drops detail.
Stride
How far the filter jumps each step. Bigger stride = smaller output.

Section 02 IntermediateA convolution, by hand

A convolution is multiply-and-add (Topic 1.1) applied to a sliding window. Here it is with no library, so the mechanism is unambiguous.

Python2D convolution and an edge detector
import numpy as np

def convolve2d(image, kernel):
    kh, kw = kernel.shape
    ih, iw = image.shape
    out = np.zeros((ih - kh + 1, iw - kw + 1))
    for y in range(out.shape[0]):
        for x in range(out.shape[1]):
            # At each position: overlay the kernel, multiply, sum.
            # A high value = "this patch matches the kernel's pattern".
            patch = image[y:y+kh, x:x+kw]
            out[y, x] = (patch * kernel).sum()
    return out

# A vertical-edge detector: dark on the left, bright on the right.
# A CNN LEARNS filters like this from data instead of hand-coding them.
sobel_x = np.array([[-1, 0, 1],
                    [-2, 0, 2],
                    [-1, 0, 1]])

edges = convolve2d(image, sobel_x)   # lights up where vertical edges are

# Stack many learned filters, then feed their feature maps into more
# convolutions. Early layers learn edges; deeper layers combine them
# into textures, then parts (an eye, a wheel), then whole objects.
The hierarchy of features

The reason deep CNNs work so well is that they build a hierarchy. The first layer learns simple things — edges, colours, gradients. The next combines those into textures and simple shapes. Deeper layers combine those into object parts, and the deepest into whole objects. Nobody programs this hierarchy; it emerges from training, and if you visualise a trained CNN's filters you can see it. This is the deep-learning promise made visible: the network learns its own features, from raw pixels up to concepts.

Section 03 IntermediateThe CNN toolkit

The building blocks of a CNN
LayerDoesWhy
ConvolutionApplies learned filtersDetects patterns, position-independently
Activation (ReLU)Non-linearity (Topic 2.4)Lets layers stack meaningfully
PoolingDownsamples (e.g. max of each 2×2)Shrinks data; adds position tolerance
ChannelsMany filters per layerDetect many patterns at once
Stride / paddingControl output sizeManage resolution through the network
Fully-connected headFinal classification (Topic 2.4)Turns features into a decision
PythonA small CNN in PyTorch
import torch.nn as nn

model = nn.Sequential(
    nn.Conv2d(3, 32, kernel_size=3, padding=1), nn.ReLU(),  # 3 colour -> 32 features
    nn.MaxPool2d(2),                                        # halve the resolution
    nn.Conv2d(32, 64, kernel_size=3, padding=1), nn.ReLU(),
    nn.MaxPool2d(2),
    nn.Flatten(),
    nn.Linear(64 * 8 * 8, 128), nn.ReLU(),
    nn.Linear(128, 10),                                     # 10 classes
)
# Train it with the exact loop from Topic 2.5 -- CNNs are ordinary
# neural nets whose layers happen to be convolutions.

Section 04 AdvancedThe vision task taxonomy

"Computer vision" is several distinct problems, each with its own output shape and models.

Types of vision task
TaskQuestionOutputExample model family
ClassificationWhat is in this image?One labelResNet, EfficientNet, ViT
Object detectionWhat is where?Boxes + labelsYOLO, DETR
SegmentationWhich pixels are what?A label per pixelU-Net, Mask R-CNN, SAM
Pose / keypointsWhere are the parts?PointsOpenPose
Image embeddingRepresent for search/similarityA vectorCLIP (Topic 6.2)
Where CNNs touch your AI-engineering work

You are unlikely to train a CNN from scratch, but they appear in your world constantly: the vision encoder inside a multimodal model that reads documents (Topic 6.2) is CNN- or ViT-based; OCR and layout parsing in your ingestion pipeline (Topic 4.5) uses vision models; and image embeddings for multimodal RAG (Topic 6.2) come from these architectures. You use them through higher-level APIs, but knowing what a convolution does demystifies why these systems behave as they do — and why, for a bespoke vision task, fine-tuning a pretrained CNN is usually the right move over training one from nothing.

Section 05 ProfessionalCNNs vs vision transformers

Since 2020, the transformer (Topic 1.3) has moved into vision as the Vision Transformer (ViT), cutting images into patches and treating them as tokens (Topic 6.2). It now rivals or beats CNNs on many benchmarks — but CNNs are far from obsolete.

The trade-off
CNNVision Transformer
Built-in assumptionLocality & translation invarianceNone — learns relationships from data
Data efficiencyGood with less dataNeeds lots of data (or pretraining)
Peak accuracy at scaleStrongState-of-the-art on many tasks
ComputeEfficientHeavier (attention is quadratic)
Use whenLimited data, edge devicesLarge data, top accuracy, multimodal

The pattern is familiar from Topic 11.2. The CNN builds in a strong human-designed assumption (locality); the transformer builds in almost nothing and learns the structure from data — and, given enough data and compute, the general approach wins, exactly as the "bitter lesson" predicts. For an application builder the practical upshot is simple: use whatever the pretrained model you are consuming happens to use, and reach for a CNN when data is scarce or compute is tight, a ViT when you have data and want peak accuracy.

Section 06 ProfessionalExercises

Do these — roughly a weekend
  1. Implement convolve2d and run the Sobel edge detector on a photo. See the edges light up.
  2. Train the small PyTorch CNN on CIFAR-10 or MNIST. Reach a good accuracy using the Topic 2.5 training loop.
  3. Visualise the learned first-layer filters. Confirm they resemble edge and colour detectors.
  4. Fine-tune a pretrained ResNet on a small custom dataset. Compare against training from scratch — note how much pretraining helps.
  5. Run an object detector (YOLO) and a segmentation model (SAM) on the same image. Observe the different output shapes.
  6. Compare a CNN and a ViT on a small dataset. Reproduce the data-efficiency gap from Section 05.
